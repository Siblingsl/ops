# OPS Desktop 灰度发布与回退操作

> **当前发布门槛未通过。** 仓库中的最新 Windows x64 Squirrel 候选未签名；生产 HTTPS/WSS、真实公网与本机模型、原生文件选择器、干净 Windows 安装/升级均未完成验收。当前状态只允许继续内部开发和隔离测试，不得作为正式客户端发布。

## 发布前条件

仅在以下条件全部满足后开始灰度：

- 用户指南所述数据流、任务边界和当前支持能力已经对试点用户说明；试点用户明确理解业务上下文仍经线上 OPS 服务。
- 生产数据库和文件已备份；新后端已通过桌面增量迁移、旧 Web 回归、HC-01 至 HC-31 与桌面后端测试。
- `OPS_DESKTOP_AI_ENABLED` 默认关闭；线上 HTTPS 证书、Secure Cookie 与 `/api/v1/desktop/channel` 精确 WSS Upgrade 配置已验证。
- 操作前检查目标分支的 CI/CD 触发条件。当前 `main` 分支 push 会触发现有 Deploy 流水线；不能假设桌面代码或文档提交不会部署线上业务站点。
- 仅签名发布机持有代码签名凭据。安装器签名状态为 `Valid`，签名发布者与批准的发布者证书一致；未签名或发布者不匹配立即停止。
- 干净 Windows x64 环境完成安装、登录、升级、卸载与本机数据保留检查；实际 HTTPS/WSS、公网 API 和本机 OpenAI 兼容 API 均完成验收。需要支持的多模态能力逐项验收。
- 第 16 节验收矩阵中的发布相关项有可复核证据。mock 结果不能替代真实模型、生产网络、代理或签名证据。

## 灰度顺序

1. 在隔离环境从旧数据库备份演练迁移和恢复；确认迁移失败时服务不会开始接收业务请求。生产发布前再次备份数据库与文件。
2. 部署包含迁移和 server/desktop 数据隔离能力的新后端。`serve` 启动会先迁移再监听；等待迁移成功并完成健康检查后才继续。不要先让旧二进制接收 desktop 数据，也不要手工重复已由程序完成的迁移。
3. 保持全局桌面开关关闭，先验证现有 Web 登录、工作区、AI、上传、SSE、推送、卡片与导出行为。安装对应的 Nginx HTTP/HTTPS 模板，核对精确 WSS 路由和原 API/SSE/上传行为，运行 `nginx -t` 后按现有部署流程加载配置。
4. 启用全局桌面开关，只在一个测试工作区开放桌面 AI 策略。先用已签名候选包验证 Secure Cookie、设备注册与撤销、一次性票据、WSS ready/心跳/断线和手动重连。
5. 在一台干净 Windows x64 试点设备上完成线上服务器 AI、本机无鉴权/有鉴权 API、公网 HTTPS API、错误证书拒绝、代理、超时与取消验证。按发布所承诺的能力逐项测试文本、JSON、工具调用、识图和图片生成；未通过的能力不得开放。
6. 试点期观察权限拒绝、WSS 断线、上游错误、取消和客户端版本分布。只有试点验收记录通过并由负责人确认后，才逐步开放其他工作区；每次只扩大一批，保留关闭全局开关的能力。

TLS/WSS 与 HTTPS 站点操作细节参见 [`../deploy/https-setup.md`](../deploy/https-setup.md)；完整部署顺序、开关约束及验收矩阵参见 [`../docs/17-Electron客户端改造方案.md`](../docs/17-Electron客户端改造方案.md)。

## 安装包与升级

首版自动更新保持关闭，采用已签名安装包人工覆盖升级。发布前先在干净 Windows 环境验证安装和升级；检查签名状态和批准的发布者，例如：

```powershell
Get-AuthenticodeSignature -LiteralPath '.\OPS Desktop-0.1.0 Setup.exe' |
  Select-Object Status, SignerCertificate
```

只有状态为 `Valid` 且证书发布者匹配时才能继续；当前未签名候选的 `NotSigned` 不满足发布条件。覆盖安装前提醒用户保存业务页面未提交内容并等待或停止进行中的本机模型调用。卸载或清理前说明 Windows 可能保留用户目录；线上作品和设备需分别管理。

## 紧急回退

1. 先关闭试点工作区桌面 AI 策略，再关闭全局 `OPS_DESKTOP_AI_ENABLED`，阻止继续建立桌面 AI 通道；通知客户端用户在设置中明确切换到服务器 AI。客户端不会替用户自动改云。
2. 保留仍能识别 `execution_location`、desktop 模型 `NULL` 字段和当前迁移结构的新后端版本，使普通 Web 继续运行。回退期间不要恢复不认识 desktop 数据的旧二进制。
3. 如需恢复旧后端，先停止 desktop 写入并备份/导出桌面元数据，停用并移除 desktop 路由与供应商引用，按专用兼容步骤处理会话模型引用，验证旧版查询后再切换。此类数据兼容回退须单独演练和审批；不能把直接执行 Down 迁移当作常规回退，也不得删除作品或对话历史。

具体回退约束见 [`../docs/17-Electron客户端改造方案.md`](../docs/17-Electron客户端改造方案.md) 第 14.4 节。
