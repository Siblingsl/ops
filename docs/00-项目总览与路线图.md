## 1. 项目章程

### 1.1 项目名称（暂定）

AI 内容运营助手（工作名，后续可改）。覆盖微信公众号和小红书。

### 1.2 一句话目标

帮助中文内容创作者用 AI 提升"选题、创作、多平台适配、发布前检查、数据复盘"的效率和质量，**最终的发布与互动由真人完成**。

### 1.3 现阶段原则

1. 不考虑盈利，优先保证能用、好用、稳定、可扩展。
2. 调研与设计先行，至少 80% 精力投入在前期阶段；设计未确认前不写代码。
3. 所有平台能力必须有官方依据；每项关键能力同时准备"官方 API 方案"和"合规替代方案"。
4. 合规优先：不使用逆向接口、Cookie 模拟登录、爬虫或任何违反平台规则的自动化手段。
5. 全过程文档化：决策写入 [90-决策与变更记录](90-决策与变更记录.md)，事实写入 [91-事实核验台账](91-事实核验台账.md)。

### 1.4 角色分工

- 用户（项目负责人）：做产品决策，确认每个阶段的结论。
- AI 顾问：负责调研、方案对比、给出推荐、记录文档；发现错误认知或设计缺陷时必须指出。

## 3. 阶段路线图

```mermaid
flowchart LR
  S1["1 定位与可行性初判"] --> S2["2 平台能力深度核验"]
  S2 --> S3["3 竞品调研"]
  S3 --> S4["4 需求与功能分级"]
  S4 --> S5["5 业务流程与交互"]
  S5 --> S6["6 数据与技术架构"]

  S7 --> S8["8 开发与测试计划"]
  S8 --> S9["9 分版本实施"]
```

| 阶段 | 目标 | 主要产出 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 1 定位与可行性初判 | 明确做什么、给谁用、哪些能力可行 | 定位陈述、用户分层、核心场景、可行性矩阵 | 用户确认定位、目标用户和关键假设 |
| 2 平台能力深度核验 | 把"待验证"尽量变成"已验证"或"不可实现" | 微信接口×账号类型矩阵、测试号实测记录、小红书官方渠道结论、AI 模型与法规结论 | 所有影响 MVP 的能力都有明确状态 |
| 3 竞品调研 | 了解现有工具，避免重复造轮子，找到差异点 | 竞品对比表、可借鉴与应避免的设计 | 用户确认差异化方向 |
| 4 需求与功能分级 | 列出完整功能，分 MVP / 后续 / 不做 | 功能清单、用户故事、验收标准 | 用户确认 MVP 范围 |
| 5 业务流程与交互 | 设计每个功能怎么用 | 流程图、页面清单、线框说明、异常处理 | 用户确认核心流程 |
| 6 数据与技术架构 | 设计系统怎么搭 | 数据模型、模块划分、AI 编排、安全、部署方案 | 架构评审通过 |
| 7 风险与合规评估 | 系统识别风险并给出对策 | 风险登记表、合规清单 | 无未处理的高风险项 |
| 8 开发与测试计划 | 可直接执行的开发计划 | 里程碑、任务拆分、测试用例、上线检查表 | 用户批准开工 |
| 9 分版本实施 | 先 MVP 后迭代 | 可用的软件 | 每个版本通过验收 |

阶段 1 到 8 不写生产代码。阶段 2 允许用测试号做接口验证，这只是验证性实验，不属于产品代码。

## 4. 术语表（面向零基础）

| 术语 | 解释 |
| --- | --- |
| 公众号（订阅号 / 服务号） | 微信官方内容账号。订阅号侧重内容推送，服务号侧重服务功能。两者能用的接口不同。 |
| 主体 | 公众号的注册身份：个人或企业（含个体工商户、组织等）。 |
| 微信认证 | 企业主体付费完成的官方认证。认证后才能使用很多高级接口。个人主体无法认证。 |
| API / 接口 | 平台开放给程序调用的功能入口。程序通过接口才能"代替人点按钮"。 |
| access_token | 调用微信接口的临时凭证，约 2 小时过期，需要定期刷新。 |
| IP 白名单 | 微信只允许已登记的服务器 IP 调用接口。 |
| 草稿箱 / 发表 / 群发 | 草稿箱存未发布的文章；"发表"使文章公开但不主动推送给粉丝；"群发"会推送到粉丝的消息列表。 |
| 第三方平台 | 微信提供的机制：一个服务商经过公众号授权，代多个公众号调用接口。做多账号或 SaaS 时需要。 |
| OAuth 授权 | 用户在平台上点"同意"后，第三方应用获得有限权限的标准方式。 |
| 分享 SDK | 平台提供给手机 App 的代码包。可以把内容送进小红书 App，由用户确认后发布。 |
| human-in-the-loop | 关键步骤必须由人确认的系统设计，本项目的核心原则。 |
| MVP | 最小可用产品：用最少的功能验证核心价值的第一个版本。 |
| 生成式 AI 服务备案 | 中国对向公众提供生成式 AI 服务的监管要求。自用不需要；对外提供服务时需要登记或备案（F-201）。 |
| 模型盲测 | 用同一批真实选题让几个候选大模型分别生成内容，隐去模型名后由人打分，用来选定使用哪个模型。 |
| 前置验证（SP） | 开发开始前用真实账号、服务器做的一次性验证实验，结果用来校准设计，不属于产品代码。 |
