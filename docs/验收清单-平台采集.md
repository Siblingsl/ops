## 0. 账号准备（**最容易卡住的一步，先做完再往下**）

验收要求「每平台 ≥10 篇、跨 ≥3 个发布日、每字段 ≥10 个有效对照」。三条**必须同时满足**。

### 公众号

- [ ] 账号有 **≥10 篇已发布**文章
- [ ] 这些文章**跨 ≥3 个发布日**
- [ ] **其中有近 7 天内发布的**（验证 D1/D3/D7 节点的唯一途径，见下方「为什么必须新发」）
- [ ] 至少有 1 篇 `1.2万` 这类取整显示的（若账号达不到，在报告里写明"未覆盖取整"）

### 小红书

- [ ] 账号有 **≥10 篇已发布**笔记
- [ ] 跨 ≥3 个发布日
- [ ] 其中至少 1 篇近 7 天发布

> **为什么必须新发**：`metric_node()` 把 `day_offset` 映射到四个节点（实测确认）：
>
> | day_offset | 节点 |
> | --- | --- |
> | 1–2 | D1 |
> | 3–5 | D3 |
> | 6–29 | D7 |
> | ≥30 | D30 |
>
> 现有 7 篇测试作品发布已 102–108 天，**64 条观测全部落在 D30**。
> 补再多的旧文也无法验证 D1/D3/D7。

## 2. 逐篇绑定（每篇作品都要做，不能批量）

红线：不提供「全部绑定」「全部确认」「全部入库」按钮或接口。

- [ ] 逐篇点「关联到平台作品」，确认后 `work.xhs_note_id` / `work.wechat_msgid` 有值
- [ ] 抽查 1 篇查库确认绑定来源是 `user_link`/`user_confirm`（不能是 `legacy_title`）：
  ```sql
  SELECT platform_binding_source FROM work WHERE wechat_msgid IS NOT NULL LIMIT 3;
  ```
- [ ] **确认 `published_at` 是真实发布时间**（不是绑定时刻）：
  ```sql
  SELECT wechat_msgid, published_at FROM work
  WHERE wechat_msgid IS NOT NULL ORDER BY published_at;
  ```
  应看到**多个不同日期**。若全部相同 → 平台发布时间未采到，**停止验收**，先查 DEV-PS49 那条链路。

## 3. 一次自动采集（先关 auto_adopt）

- [ ] 确认 `auto_adopt = false`：

- [ ] 界面点「立即采集一次」，或等调度（每日窗口 09:00–21:00）
- [ ] run 终态 `succeeded`，`accepted` 等于该平台已发布作品数
- [ ] 观测状态为 `needs_confirmation`（**不是** `valid`）：
  ```sql
  SELECT quality_state, count(*) FROM platform_metric_observation
  WHERE source='wechat_browser' GROUP BY 1;
  ```
- [ ] `metric_snapshot` 里**没有**这批数据（确认前不得入库）

## 7. 失效通知（一次真实失效）

- [ ] 让会话自然失效（或换掉登录态），触发一次采集
- [ ] 采集以 `platform_login_required` 失败
- [ ] 收到站内通知，标题形如「公众号登录已失效，需要你重新扫码」
- [ ] 连续失败 **3 次**，通知数**仍为 1**：
  ```sql
  SELECT count(*) FROM notification WHERE kind='platform_reauth';
  ```
- [ ] 重新扫码验证成功后再次失效 → 能**再收到一次**通知（否则处理后永远收不到了）

## 9. 不达标时怎么写结论

不要为了让结论好看而降低标准。按实际情况写：

| 情况 | 结论写法 |
| --- | --- |
| 篇数不足 | "仅 N 篇，未达 ≥10 篇要求，本项未验证" |
| 每字段对照不足 | "每字段仅 N 个对照，未达 ≥10，本项未验证" |
| 无近期作品 | "全部作品发布 >30 天，D1/D3/D7 节点无数据，仅验证 D30" |
| 取整未覆盖 | "账号无取整显示数值，`rounded` 路径未在真实数据上验证" |

## 附：常用查询

```sql
-- 连接状态与开关
SELECT platform, state, availability, auto_collect, auto_adopt, failure_count FROM platform_connection;

-- 作品覆盖的节点
SELECT metric_node((now() AT TIME ZONE 'Asia/Shanghai')::date
       - (published_at AT TIME ZONE 'Asia/Shanghai')::date) AS node, count(*)
FROM work WHERE wechat_msgid IS NOT NULL OR xhs_note_id IS NOT NULL
GROUP BY 1 ORDER BY 1;

-- 观测状态分布
SELECT source, quality_state, count(*) FROM platform_metric_observation GROUP BY 1,2 ORDER BY 1,2;

-- 孤儿观测（valid 但没有对应快照）——应为 0
SELECT count(*) FROM platform_metric_observation o
WHERE o.quality_state='valid'
  AND NOT EXISTS (SELECT 1 FROM metric_snapshot m WHERE m.observation_id=o.id);
```
