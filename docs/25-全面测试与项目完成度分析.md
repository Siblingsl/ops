### 1.4 自动化测试暴露的缺陷与修复（本轮实施）

#### BUG-1（S1，功能回归）：D-160 桌面 AI 闸门种子缺失，`OPS_DESKTOP_AI_ENABLED=1` 静默失效

- **现象**：桌面 E2E `desktop-creative-ui.spec.ts`「真实 Electron 业务窗」在保存本机模型时报 503 `desktop_ai_forbidden 服务端尚未启用桌面 AI`。
- **根因**：D-160（2026-11-02）把 `desktopAIEnabled` 改为运行时闸门——只读 `system_setting.desktop.ai_enabled`（默认 false），env 仅保留 `0/false` 紧急全关（`server/internal/app/runtime_gates.go:31-41`）。但 `config.DesktopAIEnabled` 字段从此没有任何读路径消费，`cmd/ops` 与 `cmd/ops-e2e` 也从未把启动配置种入 DB。dcff0c1e 修的是 Go 单测路径（`withDesktopAIEnabled` 直接写 system_bool），漏了 ops/ops-e2e 启动路径——生产按 08 文档 D-160「生产用法」以 env 开启也会同样静默失效。
- **修复**：新增 `SeedDesktopAIFromConfig`（`runtime_gates.go`）——`OPS_DESKTOP_AI_ENABLED=true` 且 `desktop.ai_enabled` 键**缺失**时一次性种入 true（与 `SeedAgentFeaturesFromEnv` 同款幂等语义：不覆盖已有值、env 显式 0 短路）；在 `cmd/ops/main.go` 与 `cmd/ops-e2e/main.go` 启动时调用。
- **验证**：新增 `TestD160SeedDesktopAIFromConfigOnlyFillsMissingKey`（config 关不写/已 false 不覆盖/键缺失种 true/env 紧急关短路）；`go vet` + `go test -run TestD160` 通过；复跑 creative-ui 原失败点越过，闸门值落库 `desktop.ai_enabled=true`。

#### BUG-2（测试契约适配）：Web E2E-22 的模型条目选择器过期

- **现象**：`agent.spec.ts` E2E-22 断言自检后能力标签可见失败（元素不存在）。
- **根因**：上一轮审计把模型条目从 `span.inline-flex` 重构为 `div[data-testid="model-usable-row"]` 行卡片（能力标签与可用性结论分行），测试选择器未同步。
- **修复**：选择器改用 `[data-testid="model-usable-row"]`，`工具调用·通过`/`看图·通过` 文本断言原样保留（不弱化）。定向复跑通过（12.2s）。

#### BUG-3（测试适配）：4 个桌面 E2E 仍在测 2026-10-30 重构前的交互

- **现象**：`agent-modes`（DEV-AW07 模式切换）、`agent-plans-questions`（DEV-AW07 计划恢复）、`agent-goals`（DEV-AW09）、`agent-workbench-aw12-layout`（主题场景）在真实 Electron 下失败。
- **根因**：`5e33da3b`（DEV-AW12，2026-10-30）把桌面对话改为「账号跟随当前账号（顶部切换器切换）+ 模型在输入台选择」，并移除了顶栏主题直出按钮（挪进用户菜单）；4 个 spec 仍按旧的「对话设置」对话框与顶栏主题按钮定位。
- **修复**（断言全部保留，仅替换交互路径）：三个 agent spec 的选账号段改用 `openDesktopAccountSwitcher` + `desktop-context-menu`（并断言 `.desktop-agent-workbench-meta` 含目标账号名）；goals 的目标面板入口在桌面形态改走「任务面板」侧栏（Web Dialog 分支保留）；aw12 主题切换改用既有 `toggleDesktopTheme` helper。4 项复跑全部通过。

#### 已知 flaky（未修根因，已加韧写法）

`desktop-creative-ui.spec.ts`「真实 Electron 业务窗」中「用户菜单 → 通知与 AI 任务」菜单项点击，在该用例完整 120s 流程中稳定失败（menuitem 在 actionability 等待期反复 detach、`.notification-panel` 永不出现）；但独立复刻实验（同 E2E 环境 + 建 + 同双 mock + 工作台漫游，v5–v7 诊断脚本）中点击 27–44ms 成功、面板正常打开，无法缩小触发条件。处理：该步骤改为「打开菜单→点通知项→面板可见」最多 3 次整体重试，最终断言始终是通知面板可见（不弱化）。连跑通过。遗留：菜单被外力关闭的根因未定位（怀疑与用例长流程中通知/用量轮询重渲染相关），见第 5 节建议。
