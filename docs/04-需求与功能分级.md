## 2. 分级规则

| 级别 | 含义 | 判定条件 |
| --- | --- | --- |
| **P0** | MVP 必做 | 缺了它主链路（S1 到 S8）走不通，或者它直接承载三大差异点之一（D-013），或者它是合规底线 |
| **P1** | MVP 应做，可砍 | 明显提升体验或效率，但缺了它主链路仍能用手工方式走通；开发排期紧张时优先砍 |
| **V2** | 后续版本 | 有价值，但依赖未定的外部条件（认证、文生图服务、更多用户），或成本明显高于 MVP 阶段的收益 |
| **不做** | 明确排除 | 违反平台规则或法律，或与产品定位冲突 |

排序原则：同级别内按 D-013 的差异点排序，即账号记忆 > 一稿双平台 > 合规把关与发布衔接。

例外：M13 系统智能体（D-117）在 MVP 之后新增，其 P0 / P1 只表示该模块首次交付内的优先级（P0 首次交付必须具备，P1 可在 P0 验收后补齐），不计入第 9.1 节的 MVP 统计。

本阶段新确认的范围决策：

- **D-018**：漫画能力拆分。MVP 做文字部分（角色设定卡、分镜脚本、逐格文案和对白），AI 出图和跨图角色一致性放到 V2。
- **D-019**：MVP 只做单用户登录，数据模型预留成员和角色字段（历史范围）。
- **D-036**：多租户工作区 + 邀请码多成员协作（开放自建、一人多工作区、owner/editor）。

### 3.1 平台与账号类型组合（D-033、D-048）

账号类型在创建时从预设清单中选定（D-008、D-048），**创建后可在同一平台内迁移**（D-123）：设置页提供"修改类型"入口，更新 API 需显式传 `confirm_type_change=true` 才放行，缺失时返回 409 `confirm_required`；跨平台不支持迁移，仍需新建账号。迁移后账号下已有作品按自身 `content_format` 快照保持原类型，检查、推送与打包行为不变；未采用的历史计划槽位仍是旧类型，需重新生成并启用方案。业务定位（领域、受众、人设、支柱、风格）与可选的"类型补充说明"可随时调整。类型决定作品的编辑器、检查项和发布方式；每日推荐、选题、方案与大纲都必须匹配账号类型及其领域相关性。每个类型都必须有真实工作流支撑，未实现的能力不得作为类型提供。

| 平台 | 账号类型 | 编辑器 | 发布方式 | 级别 |
| --- | --- | --- | --- | --- |
| 公众号 | 长图文 long_article | 完整编辑器（标题、加粗、列表、引用、链接、图片） | 图文消息草稿（news） | P0 |

**派生规则**（派生只允许跨平台，D-023；D-048 首批不新增派生路径）：

| 源类型 | 目标类型 | 级别 | 说明 |
| --- | --- | --- | --- |

## 5. P0 / P1 功能的用户故事与验收标准

格式：**故事**（作为……我想……以便……）；**验收**（给定 / 当 / 那么）。同一模块中相近的功能合并描述。

### M1 工作区与账号

**FR-M1-01 至 FR-M1-05**
- 故事：作为创作者，我想在一个地方管理我所有的公众号和小红书账号，以便切换账号时内容不会串。
- 验收：
  1. 给定未登录，当访问任意页面，那么跳转登录页；登录后空闲超过设定时长自动退出。
  2. 给定已有公众号 A 和小红书 B，当切换到 B，那么选题、作品、素材（仅 B 归属和共享的）、复盘只显示 B 的数据。
  3. 给定录入 AppSecret，当保存后再次查看，那么只显示脱敏值（如前 4 位加星号）；数据库中不存在明文。
  4. 给定凭证正确但服务器 IP 不在白名单，当点击连通性检测，那么提示"IP 未加入白名单"并显示需要添加的出口 IP。

### M13 系统智能体（D-117）

**FR-M13-01、FR-M13-02**
- 故事：作为运营者，我想在一个对话页里用自然语言查询和操作系统，以便不必在多个页面之间来回找功能。
- 验收：
  1. 侧边栏顶部有“智能体”入口；进入后可新建、搜索、置顶、改名、删除对话；对话只有本人可见。
  2. 模型选择器只列出通过“工具调用”自检的模型；默认使用“智能体对话”路由，未设置时用默认路由；没有可用模型时显示去模型配置页的引导，输入框不可用。
  3. 回复流式显示；运行中可停止；最后一次运行没有执行过任何卡片时可重新生成或编辑最后一条消息。
  4. 刷新页面后，服务端仍完成运行，页面恢复后显示完整回复。

**FR-M13-03、FR-M13-04、FR-M13-05、FR-M13-07**
- 故事：作为运营者，我想让智能体替我查数据、准备操作，但每一次修改都由我确认，以便既省事又不失控。
- 验收：
  1. 给定用户问“这周哪些作品还没检查”，那么智能体自动读取并回答，不产生任何卡片，业务数据不变。
  2. 给定用户要求修改，那么智能体生成操作卡片，显示对象、修改前后与风险标识；用户点击执行前业务数据不变（HC-26）。
  3. 卡片逐张执行；不存在“全部执行”按钮或批量执行接口（HC-27）；一次运行最多 5 张卡片；同一作品同时最多 1 张修改正文的卡片。
  4. H-01 至 H-09 与记忆确认的卡片按 16 文档第 5.6 节显示门槛控件；H-04 的处理方式不预选；写入公众号草稿需二次确认“写入公众号草稿箱（不会发表）”。
  5. 不可逆操作（彻底删除、删除账号、转让所有者等）需要二次确认，删除账号需输入账号名称。
  6. 一批卡片全部执行或拒绝后，智能体自动读取结果继续；连续 10 次后提示用户发消息。
  7. 不存在发表、群发、定时发布工具；用户要求发表时，智能体说明只能写入草稿或生成发布包，并给出链接。

**FR-M13-06**
- 验收：
  1. 给定用户消息中没有写出观点，那么“保存观点”卡片中观点为空，必须用户亲自填写才能执行；智能体不能代写观点（HC-29）。
  2. 给定智能体用自己写的文字修改段落正文，那么卡片不能创建，智能体须改用生成工具或用户原文。
  3. 用户在卡片上亲自修改的内容视为本人填写。

**FR-M13-08（P1）**
- 验收：
  1. 图片 ≤ 20MB 且像素 ≤ 1600 万，文本为 UTF-8 的 txt/md 且 ≤ 1MB，每条消息最多 6 个附件；超限即时提示。
  2. 图片保存为作品图片、md 保存为素材，都需要卡片执行。
  3. 模型未通过看图自检时，提示“当前模型不能看图”，图片仍可保存或用于数据截图识别。

**FR-M13-09、FR-M13-10、FR-M13-11**
- 验收：
  1. 同工作区其他成员（包括所有者和超管）访问他人对话返回“不存在”（HC-31）。
  2. 观察者只能查询，没有卡片；所有者关闭观察者使用后，观察者看不到入口。
  3. 消息中疑似包含密钥或密码时拒绝发送并提示去设置页；模型请求、对话记录和卡片中不出现密钥原文（HC-30）。
  4. 修改密码、导出数据、填写凭证或模型密钥、加入 / 切换 / 退出工作区、超管代访问、退出登录时，智能体不执行，只给出对应页面链接或操作位置（16 文档附录 B.1）。
  5. 卡片执行的操作出现在操作日志中，标注“来自智能体”；智能体的模型调用在用量页按“智能体对话”统计，达到每日上限后暂停。

**FR-M13-12（P1）**：所有者可在“智能体设置”中关闭智能体、关闭观察者使用、禁止成员自选模型；其他角色只读。

| FR-CL05 | 审阅退回与轮次 | 暂缓，待协作证据 | 现有协作路径和 H-09 竞争安全需保持 | 正式退回、轮次表、必须改稿才能重送审 |
| FR-CL06 | 素材版本与依赖 | 应补当前依据一致性校验 | 当前引用依据变化校验、到期边界、重新检查指引 | 素材版本库、固定版本绑定、历史全文复制、rebind |
| FR-CL07 | 完整离线归档 | 暂缓，待离线使用证据 | 准确说明现有导出和备份覆盖范围 | 新归档任务、历史数据打包、新权限和未经验证的容量/期限参数 |

### 11.3 FR-CL01：恢复范围与内容结构

用户要的是不丢失、不误恢复稿件。版本功能先声明每种形态和历史版本的可恢复内容，不能显示笼统的“完整恢复”却只处理段落。

1. 恢复前读回最新稿件、等待保存完成，显示差异和缺失依赖。旧卡片/漫画版本若没有足够结构，拒绝恢复并保留只读预览，不能先删段落再发现无法重建。快照后新增的作品图片保留在历史图片之后，预览明确显示数量。
2. 结构补齐范围为本作品标题、摘要、观点、大纲、段落、卡片、分格/气泡、图片引用与顺序、封面选择/裁剪、话题及主题标识；不覆盖账号自定义主题值、全局角色/素材或成员设置。
3. 恢复使用同一事务和当前修订校验；先保存当前稿，再恢复目标结构。引用图片已删除/不属于本作品授权范围时整次拒绝，不补造图片、不部分成功。
4. 恢复不回放发布事实、表现数据、检查/审阅凭据。内容改变使 H-04/H-09 失效；只有大纲语义改变才重做 H-03，不要求作者为恢复标题重复确认相同大纲。
5. 本阶段不保证所有旧图片长期可恢复，预览必须明确资源状态；不承诺历史主题按像素复现。

验收：长文/卡片/漫画分别验证范围、关联和顺序；不支持旧版本、缺文件和并发场景均保持当前稿不变；同作品批注与关联不因删除重建段落误丢失。

### 11.4 FR-CL02：一次打包的完整性与一致性

- 下载所需的文字、图片列表与顺序来自同一已保存修订；构建期间改稿则明确失败重试，不返回文字和图片来自不同稿件的包。
- 所有必需图片读取、数据库扫描、文件写入和 ZIP 结束均成功后才发成功制品；缺图/损坏不能 continue 后仍成功。
- 现有复制/分享/下载入口保持，不增加历史交付列表；各次操作展示所依据修订，不保证不同时间重新下载取得同一历史包。
- 微信推送继续复用原 push_record、覆盖保护、额度与 H-05，不把小红书包写进微信日志。结果不确定的故障核验单列，不能自动重推。

验收：缺第 N 张图片、读写失败、数据库扫描错误、构建中修改和普通完整下载；均有清楚结果，错误包不得伪装成功。若要长期重复取得同一历史包，须另行确认需求。

### 11.5 FR-CL03：原回填流程内安全更正

- 已发布作品本来可再次回填；界面提供明确的“更正发布记录”，先显示原值、拟改值、原因和只读节点影响，再由用户确认。更正契约显式使用 `mode=correction`、`base_publish_revision` 和 `reason`；预览不写业务数据，提交仍由服务端重新校验。首次回填继续走 H-07。
- 更正请求必须用独立的发布元数据基准防止并发覆盖；不得使用代表正文/结构的 work.revision。首次回填继续兼容旧请求；已发布作品的旧式变更请求若未带新基准，只允许无变化重放，否则返回 409 引导重新读取并使用更正流程。
- URL/时间、`wechat_msgid` 与受影响节点必须在同一事务校验并提交；日期重算按上海日历日差预计算整组节点。目标键冲突、负偏移或微信 API 行的文章 ID/原日期依据与现值不一致时，日期更正整体失败；只改合法链接且不改日期仍可独立提交。
- 更正前后值、原因、操作者写现有审计，保留遵守现有 365 天，不承诺长期事件历史。重复相同值不产生重复版本或假更正。
- 保持当前已发布状态和原锁定值，不改正文、平台实际内容或自动判定下架；历史基线不补造当年的操作者。
- 暂不新增“撤销误标已发布”，也不要求删除正确数据作为纠错前提。

验收：跨上海日期、节点冲突/键交换、未知原统计日、并发更正及重复请求；任一失败不能出现发布值成功但数据偏移未同步。

### 11.6 FR-CL04：数据变化后的可信使用

1. 新增/合并、修改、删除、截图确认、CSV/粘贴、微信同步/匹配、发布时间重算，以及改变复盘特征的作品标题/话题/发布时间/正文长度等操作，均使受影响账号的偏好依据待验证；只改互动、同总和换值和删到零条也不能漏掉。
2. 保留现有同来源同节点去重合并及 NULL/0 区分（DR01）；不强改为“必须另开编辑表单才可合并”。指标记录使用单调修订号；编辑和删除必须提交读取时的 `base_revision`，过期请求以 409 拒绝。所有实际变化在同一事务记录前后值、来源及操作者/系统身份；无变化写入不生成变更审计，不保存截图原文件到审计。
3. 样本不足时保留旧偏好记录（DR08），但未验证为当前适用时不送入生成；历史展示说明统计依据及适用性。使用者能区分当前可用、等待重算、样本不足和旧记录未验证。规则重算不调用模型，不因数据变化自动付费生成报告。
4. 偏好输入版本必须覆盖实际参与 perfSamples 的账号样本集合与特征字段，包括指标、标题、发布时间、话题、正文长度和影响样本窗口的作品增删；不得只比较阅读和/数量。
5. 复盘报告依据追踪本期暂缓。报告继续用 H-08 逐条人工采纳，不加 report basis 状态或额外 stale acknowledgement；已采纳选题/记忆不自动回滚。

验收：所有真实样本输入变更、删到零条、样本窗口边界、重算竞争/重复提交、样本不足保留记录且暂停无效注入；原 DR01/DR08 的合法语义保持。复盘报告陈旧状态不属于本期验收。

### 11.7 FR-CL05：正式审阅退回暂缓

目前可用批注→作者修改→重检→再次审阅完成主要协作。先验证此路径及现有 approve 的当前修订/权限/状态竞争检查。

正式退回需要真实协作反馈支撑：确实经常无法区分“未看/退回”，或意见/责任交接反复丢失。满足后另审最小退回原因与通知；不直接启用完整轮次表，也不要求必须制造新内容修订才能解释后重送审。

### 11.8 FR-CL06：当前素材依据变化校验

- 检查记录保存当前引用依据摘要；完成检查、审阅通过及实际交付前服务端重新比较。素材正文、来源、有效期、可见范围、删除状态改变后旧检查不能继续放行；普通写稿不因旧检查依据变化而阻塞。
- 覆盖整篇 work_material 和段落 material_ids，引用缺失/不可见也算变化；仅标签/排序变化不视为事实依据变化。
- valid_until 为最后有效日，按上海日期在次日零点过期；已在检查时过期的素材仍按既有逐项核实流程处理。
- 不创建素材版本/rebind，不自动改正文；摘要只能证明输入变没变，事实仍由人核实。没有摘要的旧检查下次交付前需重检，不影响已发布事实。新检查的事实项仅在旧、新依据摘要一致时继承逐项确认；依据变化后事实项须重新核实，其他类别沿用既有指纹规则。

验收：检查后修改/删除/恢复素材、跨到期边界、引用新增/移除、范围变化、仅标签变化；两种引用来源与直接 API 均不能绕过。

### 11.9 FR-CL07：完整归档暂缓

现有单篇 Markdown、摘要/素材 CSV、复盘导出与运维备份保留，并准确注明图片是否仍需登录、是否包含正文、是否可恢复系统。它们不等于完整离线包。

只有确认存在经常离线交接/长期独立阅读的需求，才另审“单篇可读内容+合法配图”的最小导出；默认不含素材全文、成员操作、表现修订或对话，不预设 owner-only、200 MiB/500 文件/24 小时规则。
