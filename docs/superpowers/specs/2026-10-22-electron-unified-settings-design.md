# Electron 统一设置中心与本机配置嵌入设计

> 日期：2026-10-22；状态：用户已确认“同一主窗口内呈现、保留受信任的本机视图”方向；本文为待审设计稿，尚未开发。
> 范围：Electron 客户端设置入口、设置导航、窗口组合和权限呈现。普通 Web 行为不变；不改变既有业务 API、数据表或保存规则。

## 1. 背景与问题

当前 Electron 有两套设置呈现：`DesktopSettingsHost` 在业务页上创建统一设置对话框；其中“客户端连接与模型”又显示一个按钮，通过 `ops-desktop://ui/settings` 打开新的 `BrowserWindow`，加载 `ops-desktop://settings/`。因此用户从设置里进入本机配置时会离开当前设置对话框，看到第二个顶层客户端设置窗口。

这不是遗漏的按钮，而是 D-126 §10.5 明确保留的架构：本机设置页有受限 preload，可操作本机密钥库、设备和平台浏览器；线上业务页没有 preload。IPC handler 还校验调用方必须是本机设置窗口。当前 `DesktopPanels.tsx` 的“打开本机设置窗口”按钮、`main.ts` 的 `showSettingsWindow/createLocalWindow` 与 `assertTrustedLocalSender` 是这条链路的代码落点。

原生客户端页的七个标签也混合了不同作用域：本机 AI 与模型、个人设备、工作区共享策略、平台账号类型。不能把整页统一标成“管理员设置”。D-132 已规定桌面账号设置只操作当前账号；账号类型迁移已经在该页面提供。客户端页仍保留的跨账号类型选择与该决定不一致。

## 2. 目标与成功标准

1. 在线设置始终留在当前主 `BrowserWindow`；不因打开本机配置再创建第二个顶层窗口。离线或尚未登录时，本机设置复用当前可见应用窗口，不新建设置窗口。
2. 在线设置共用一个设置入口、一个分类导航和一套当前账号/工作区标题上下文。本机配置作为“本机与系统”下的常规设置项，不再出现“打开本机设置窗口”按钮。远程业务页尚未可用时，当前窗口显示本机设置/连接恢复界面。
3. 本机设置继续由包内 `ops-desktop://settings/` 内容和受限 preload 承载。线上页面只收到主进程发起的单向菜单导航通知，不获得模型密钥、设备私钥、文件系统或通用 IPC 能力。
4. 工作区 AI 策略由 owner 管理；editor、viewer 和系统管理员遵循已有服务端角色与代访问规则。角色只控制其原来获准的工作区操作，不把成员本机密钥交给 owner。
5. 现有设置表单、确认、重新认证、API、数据保存、账号上下文与本机 AI 安全约束保持原语义；只调整呈现位置、导航归属及必要的 UI 导航桥。
6. 设置关闭后，当前业务路由、编辑器草稿、滚动位置和正在运行的业务页面继续保留。切换账号/工作区时，本机设置视图不保留上一身份的数据。
7. 打开设置不增加顶层窗口；在 960×640、1440×900 及 100%/125%/150% Windows 缩放下，正常在线时本机视图与统一设置内容区保持对齐；窗体变化时无横向溢出、焦点丢失或视图残留。

## 3. 方案比较与选择

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| 保留独立设置窗口，只合并七个本机标签 | 风险最低，但仍有第二个客户端设置窗口，未解决用户提出的入口割裂 | 不选 |
| 把本机设置 API preload 加给线上业务页，让 React 直接调用 | 表面上最容易合并；会把随线上更新的页面置于本机设置特权边界内，密钥/设备能力隔离变弱 | 不选 |
| 统一设置窗由 React 保持导航，本机设置以隔离的 `WebContentsView` 嵌入设置内容区 | 单一设置导航与当前 React 表单可复用；本机表单继续运行于受信任本机来源。线上主页面只接收一个单向、无参数的原生菜单导航通知，不获得本机设置 API | **采用** |

Electron 官方 API 支持在一个 `BrowserWindow`/`BaseWindow` 中组合多个 `WebContentsView`。设计使用本机视图覆盖统一设置窗的内容区，业务 WebContents 保持原位。Electron 文档同时要求校验 IPC sender、避免向远程内容暴露 Electron API，并在宿主窗口关闭时显式关闭子视图 WebContents：[WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)、[BaseWindow](https://www.electronjs.org/docs/latest/api/base-window)、[Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

## 4. 统一设置结构

继续使用 D-136 已实现的五类导航：个人、当前账号、工作区、数据与工具、本机与系统。本机页的七个标签不再嵌套为第二套左侧导航，归并成以下入口：

| 统一设置位置 | 显示内容 | 数据与权限归属 |
| --- | --- | --- |
| 工作区 / 桌面 AI 策略 | 工作区启用状态、是否允许 editor 使用各自的客户端端点 | 工作区级；owner 可写，服务端仍检查角色、重新认证与代访问状态 |
| 当前账号 / 平台账号与凭证 | 当前账号资料、平台连接状态、平台登录入口、账号类型迁移 | 当前账号；账号切换仍由顶部统一入口负责；不提供其他账号选择器 |
| 本机与系统 / 客户端连接 | 服务连接、执行模式、WSS 状态、切换提示 | 当前 OPS 用户与工作区在此设备上的运行状态 |
| 本机与系统 / 本机 AI 配置 | 本机模型、代理与密钥、自检、任务映射及辅助能力去向 | 当前 OPS 用户、工作区和设备；API Key 仅由 Windows 用户级加密存储保护 |
| 本机与系统 / 账号与设备 | 当前 OPS 身份摘要、重新认证、本人设备、清理本机账号数据、平台浏览器与残留 profile | 本人/当前设备；不得让 owner 查看其他成员设备私钥或本机配置 |
| 本机与系统 / 诊断与关于 | 脱敏诊断、客户端版本、服务信息 | 只读；诊断继续按现有脱敏契约生成 |

归并规则：

- 原“连接与模式”进入“客户端连接”。
- 原“本机模型”“能力自检”“任务映射”进入“本机 AI 配置”的分段内容，保留已有保存与自检动作，不在打开设置时自动请求模型或产生费用。
- 原“账号与设备”进入统一的当前账号/本机设置。平台连接入口仍固定到当前账号；账号类型从本机面板移除，使用 D-132 当前账号页面已有的类型迁移表单。
- 原“工作区策略”移入工作区设置，并在非 owner 视角下显示只读状态或不显示写控件；服务端拒绝仍是最终授权依据。
- 原“诊断与支持”与“关于”合为一个入口；导出内容、版本口径不变。

## 5. 窗口、视图与信任边界

在线正常使用时当前业务 `BrowserWindow` 是主窗口；业务不可用时沿用现有故障窗口。设置视图只附着到当前可见窗口，不因打开设置创建新的顶层窗口：

```text
BrowserWindow（正常在线时的业务主窗口）
├─ 业务 WebContents：线上业务 Origin、仅含单向菜单导航订阅的最小 preload、保留原页面与草稿
└─ 统一设置对话框（React，原 DesktopSettingsHost）
   ├─ 唯一设置导航、标题、权限提示与关闭/离开保护
   └─ 本机配置内容 WebContentsView：ops-desktop://settings/embedded/<panel>
      ├─ 独立 ops-settings Session
      ├─ 仅本机静态资源与受限 preload
      └─ 只绘制当前本机设置内容区，不绘制第二套标题栏或侧边导航
```

React `DesktopSettingsHost` 继续负责统一导航、路由、当前账号/工作区标题、未保存保护和业务设置表单；Electron 路由根层必须在登录页、首次设置页及已认证业务路由均保持设置宿主可用。未登录时只开放本机与系统配置，账号/工作区数据和写操作仍在原认证边界内。在线且 React Host 可用时，选中本机设置项后，主进程将本机 `WebContentsView` 附着到同一 `BrowserWindow` 的内容视图中，覆盖统一设置窗的右侧内容区；统一 React 导航和标题仍可见。关闭或切换到非本机设置项时移除该子视图，恢复原 React 内容区。底层业务 WebContents 不重载、不被替换。

若业务页面未能加载（启动超时、离线或版本不兼容），原生连接菜单、重试和诊断仍需在当前可见应用窗口中工作。主进程把同一受信任本机视图扩展到该窗口的内容区，显示本机设置/恢复界面；恢复成功后销毁该视图并回到业务页面。此状态沿用本机页面自身的导航，因为线上 React Host 不可用；它仍复用现有可见窗口，不创建新的 settings `BrowserWindow`。若当前可见窗口是既有离线窗口，则在该窗口内完成相同呈现与恢复，不额外弹窗。

本机视图从严格白名单加载四个面板 ID：`connection`、`ai`、`account-device`、`diagnostics`。不得接受调用方提供任意 URL、文件路径、HTML、脚本或窗口边界。主进程根据当前 `BrowserWindow` 内容区域尺寸、固定的设置对话框布局参数和窗口缩放更新子视图 bounds；bounds 计算只依赖应用自有窗口尺寸，不读取或脚本注入线上 DOM。React CSS 与主进程共用固定布局契约，验收时验证对齐。

原生菜单里的“AI 连接设置”也进入当前可见应用窗口。在线业务页面可用时，主进程仅向确切的业务主 frame 发送一个无参数事件；独立的 `business-ui-preload` 只向 React 暴露 `onOpenSettings(callback)` 订阅，不暴露发送方法、Electron API、页面路径、账号数据或本机设置 API。React 收到事件后自行导航到 `/settings/local/connection`，保留当前业务路由作为设置背景。preload 仅保留一个待处理布尔事件，避免事件早于 React 订阅时丢失；主进程也需在主 frame 加载完成前暂存一次菜单请求，加载到允许的业务 origin 后再发送。未认证时该入口仍能打开本机连接面板，但在线账号/工作区表单保持认证门控。业务页不可用时由主进程在当前可见窗口中直接呈现本机恢复界面。原生菜单发往非业务来源、子 frame 或已销毁 WebContents 时丢弃。不得以通用 IPC 或脚本注入替代。

### 5.1 本机视图 IPC 契约

- IPC sender 按精确的本机 `WebContents` 实例注册表校验，并同时校验 `ops-desktop://settings` origin、允许的嵌入路径、主 frame 和主进程生命周期；不能仅以 `BrowserWindow` ID 判定可信，因为子视图与主窗口共享宿主窗口。
- 现有本机设置方法保留独立命名、结构化参数、大小/枚举校验和最小返回字段。不得暴露 `ipcRenderer`、任意 URL 请求、文件路径访问或命令执行。
- 业务 WebContents 继续不具备 `opsDesktopSettings`，也不能向主进程调用该导航通知。它只通过 `business-ui-preload` 收到主进程发起的固定 `open settings` 事件；preload 不转交 Electron event 对象，不暴露 `ipcRenderer`。该事件不含身份/账号/URL，也不能读取或写入本机数据。
- 本机视图只在当前可见的主/故障窗口中创建；在统一设置打开期间切到在线面板时将 View 脱离显示但保留实例，回到本机分类时复用当前面板与表单状态；关闭统一设置、切换账号/工作区、父窗口销毁或应用退出时，经离开保护后显式销毁其 webContents、移除 View 并清除身份绑定。
- 本机页面只向主进程上报 dirty、busy 两个布尔状态；统一设置离开保护纳入这两个状态，但不读取或转发表单内容与密钥。窗口主题、减少动效、Escape、Tab/Shift+Tab、焦点归还和未保存表单确认按统一设置规则执行。正在保存时不能离开；用户确认丢弃前不得销毁本机视图。

### 5.2 本机设置内容区布局

- 嵌入模式隐藏本机页面原应用标题栏、七标签导航、重复页面标题和重复“关于”页脚，仅保留当前面板正文及其原有状态行。
- 本机 View bounds 与统一对话框右侧 pane 的左上角、尺寸和滚动区一致。布局常量有一个项目内权威来源；主进程不得执行远程 JavaScript 查询 DOM 位置。
- 视图打开时将键盘焦点交给本机面板；Escape 先按统一离开保护关闭本机 pane，焦点回到对应设置导航项。Tab 循环不允许落入已被覆盖的远程 pane 控件。
- 窗口调整大小、最大化、恢复和系统缩放变化时同步更新 bounds；不依赖启动时的一次性尺寸。

## 6. 账号与权限矩阵

| 用户状态 | 统一设置导航 | 工作区 AI 策略 | 本机模型/映射 | 本人设备 | 其他成员本机信息 |
| --- | --- | --- | --- | --- | --- |
| owner，策略允许 | 显示获准项 | 可读写，重新认证/代访问规则不变 | 仅管理本人当前设备；成员端点规则照旧 | 可列出/撤销本人设备 | 不可读 |
| editor，允许成员端点 | 显示获准项 | 不可写 | 只可配置/使用本人当前设备，维持既有策略与能力限制 | 可管理本人设备 | 不可读 |
| editor，禁止成员端点 | 显示获准项与原因 | 不可写 | 不得通过客户端端点发送工作区上下文；服务器 AI 路径不变 | 可管理本人设备 | 不可读 |
| viewer | 设置可读部分按现有规则展示 | 不可写 | 首版不开放客户端模型 | 可管理本人设备 | 不可读 |
| 系统管理员/代访问 | 系统管理项按原 `is_system_admin` 显示 | 系统管理员身份不能替代 workspace owner；代访问禁止桌面中转 | 不得借代访问配置客户端模型或通道 | 只按真实登录用户管理本人设备 | 不可读 |

UI 依据安全上下文显示角色和可用状态，但服务端授权仍为权威。上下文缺失、认证过期或工作区不匹配时，写入项禁用并说明重新登录/认证；不按前端 role 隐藏结果推定后端已授权。owner 关闭策略、editor 失去允许或成员身份变化时，既有主进程授权/取消行为保持不变。

## 7. 流程与异常处理

1. **从常规设置进入**：React 设置导航切到本机面板；检查当前可见主窗口及所选面板的权限上下文（纯本机配置不要求在线登录，账号/工作区内容仍按认证与角色门控）；创建/显示本机子视图；加载白名单面板。加载失败时在统一 pane 内显示错误与重试，不打开新窗口。
2. **从原生菜单进入**：线上 Host 可用时，唯一 UI 导航通知令其打开本机连接面板；必须保留原业务路由和编辑内容。未登录时仍可看本机连接设置，账号/工作区业务内容按认证状态门控。Host 未能加载时，在当前可见窗口内显示本机恢复界面并保留重试/诊断；不得创建独立设置窗口。
3. **切回业务设置或关闭**：统一设置 Host 先检查 React 表单与本机视图的 dirty/busy 状态；允许后切换到在线面板时暂时脱离本机 View，但保留实例直到统一设置关闭；关闭前按确认结果销毁本机 pane。取消离开时恢复当前 pane 和焦点。
4. **账号或工作区切换**：进入切换流程前关闭本机子视图并清理正在显示的目标、敏感内容和 role 快照。新身份通过原线上会话重新确认后才允许创建新 pane。
5. **平台登录**：仍由业务当前账号页带固定账号 UUID 与平台发起。设置 Host 将目标作为一次性本机 intent 交给主进程；本机视图只显示该目标，不允许挑选其他账号。关闭/取消/超时沿用 D-131 登录流程。
6. **业务服务不可用**：原故障窗口继续作为当前可见应用窗口；重试与脱敏诊断可用，本机配置仍留在该窗口中，不另开设置 BrowserWindow。业务 API 项显示离线/不可用，不展示缓存角色为当前授权。
7. **视图加载或布局错误**：保留统一设置导航；右侧报告“本机设置暂不可用”，允许重试/返回，不静默切到另一个窗口，不丢失 React 背景页。
8. **子视图销毁**：父窗口关闭、异常退出、面板切换和 app quit 都执行一次性清理；重复清理安全。主窗口事件不复用远程页面的 IPC allowlist。

## 8. 数据与兼容边界

- 不新增/修改数据库迁移、服务端 API、AI 执行路由、模型供应商契约、角色 ACL 或平台采集能力。
- `safeStorage`、`desktop-config.json`、独立 `ops-settings` Session、平台 profile、WSS 与设备证明的归属及格式不变。所有 API Key、代理凭证与私钥仍不进入 React 设置页、线上业务 API、日志或诊断。
- 工作区策略移入现有工作区设置呈现，可使用现有 `GET/PUT /desktop/policy` 与 CSRF 流程；owner/代访问权限由服务器校验。若当前浏览器 API helper 无法满足该 endpoint 的既有 CSRF/身份契约，保留调用在本机桥后再作为该 workspace pane 的专用 adapter，不新增权限。
- 账号类型迁移只保留 D-132 当前账号页面的实现；移除本机设置里的跨账号下拉 UI。迁移接口与确认语义不变。
- 普通 Web 不显示本机设置、本机 IPC 或本机密钥说明的可执行入口；Web 的路由、表单、外观与保存行为保持不变。
- 历史设置深链 `ops-desktop://ui/settings` 归一化到统一主窗口设置 pane。已安装旧客户端的远程页面与新客户端的混布应在不崩溃、不误开第二窗口的情况下落到统一设置入口或显示“请更新客户端”提示。

## 9. 验收标准

### 9.1 窗口与交互

- 从统一设置导航、原生客户端菜单、当前账号平台连接入口打开设置时，`BrowserWindow.getAllWindows()` 不因设置打开新增顶层设置窗口；业务离线时也复用当前可见窗口。
- 设置分类只有统一的五组导航；本机配置不出现第二套侧栏或设置标题栏；切换本机/在线面板仍在同一个对话框与主窗口内。
- 打开/关闭设置后，业务 URL（含 query/hash）、账号选择、编辑器正文、草稿与滚动位置保持；本机视图不存在时远程业务页仍可交互。
- 在 960×640、1440×900 与 100%/125%/150% 缩放下验证 bounds、内外滚动、窄宽换行、最大化/恢复、Escape、Tab/Shift+Tab、焦点返回和关闭边界。
- 本机面板保存失败保留输入；保存中不能切走；关闭前未保存按确认结果处理。

### 9.2 权限与信任边界

- 业务远程主 frame、iframe、其他 origin、伪造 URL、DevTools/新建 WebContents 均不能调用任何 `settings:*` 本机 IPC。
- 只有注册过的本机 WebContentsView 主 frame，且当前 URL 为允许的 ops-desktop://settings/embedded/<panel>，可调用原有结构化本机方法；该 View 只允许加载本机协议白名单路径，拒绝远程导航、重定向和新窗口。
- 原生菜单通知只由主进程发起，且只发给业务主 frame；线上页面不能发送该 IPC，也不能借通知传入 path/query/body。React 自己发起的设置导航仍使用既有固定 `ops-desktop://ui/...` intent allowlist。
- owner/editor/viewer、系统管理员、超管代访问及策略关闭状态分别覆盖；测试服务端对写操作仍返回原权限结果。
- owner 看不到成员本机密钥/设备私钥；viewer 仍可按现有规则管理本人设备；工作区切换后上一身份模型、设备、账号和平台登录目标不在新 pane 闪现。

### 9.3 业务与运行回归

- 本机模型保存/删除/自检、任务映射保存/生效、WSS 连接/断开、账号本机数据清理、平台登录、诊断导出逐项复用既有接口并完成行为对照。
- workspace policy 写入成功/失败、重新认证过期和 owner 收紧策略保持既有 API 与执行效果。
- 当前账号平台登录与账号类型迁移仍使用当前账号；不存在本机跨账号类型选择器。
- 离线时重试、诊断与本机设置复用现有故障窗口；设置前后 `BrowserWindow` 数量不增加。关闭/退出后所有子 `WebContents` 均关闭，无孤儿进程/视图。
- Web 核心回归、Electron 本机真实窗口 E2E、`typecheck`、相关单测和 build 通过；HC-01～HC-25 与 HC-26～HC-31 全部保留并按仓库要求验收。

## 10. 实施范围与顺序建议

实施计划在本稿经用户审阅后另行编写。预计包含：

1. 将 Electron 设置宿主与菜单事件订阅提升到登录/认证路由共同的根层；未认证时仅开放本机设置。整理统一导航元数据与角色/作用域显示，确认当前账号/工作区上下文。
2. 本机设置 HTML 增加嵌入面板模式；移除重复标题、导航与跨账号类型 UI；保留现有单项动作。
3. 主进程为业务 BrowserWindow 增加并管理本机 `WebContentsView`，实现固定面板 allowlist、bounds 更新、精确 sender 注册、关闭/账号切换清理与离开保护。
4. 将 workspace policy 放入工作区设置，将账号类型留在当前账号设置；复用现有 endpoint 与保存/确认逻辑。
5. 统一原生菜单、业务设置入口和平台登录 intent；关闭旧的第二个 settings BrowserWindow 路径并归一化深链。
6. 按第 9 节矩阵运行安全、角色、交互、离线、尺寸/缩放、Electron 窗口与业务回归，记录未覆盖项。

代码改动完成前，不删除旧处理逻辑；只有所有入口与旧版本兼容测试通过后，才在对应实现步骤中退役已确认无调用者的独立窗口分支。

## 11. 文档同步与决策
