## 0 口径

### 0.1 什么叫「真实闭环」

一个闭环只有同时满足以下五条，才能在本文件写 `已闭环`：

1. **真实外部系统**：真实公众号 / 小红书 / 模型供应商 / SMTP / 真实部署环境，不以 mock、夹具、模拟器代替。
2. **真实用户路径**：从桌面端真实用户入口完成，不是只调一个 API 或只跑一个单元测试。
3. **失败与恢复**：至少覆盖一次可预期的失败（鉴权过期、平台拒绝、网络失败、限流 429/403、权限不足等），并证明用户能看到可读原因、能恢复或安全停止。
4. **可复核证据**：命令、时间、结果、截图 / 录屏、脱敏数据行、日志摘要，落在 `docs/42-evidence/RC-xx/` 或既有 `docs/41-evidence/`。
5. **台账同步**：`docs/42` 状态改为 `已闭环`，并同步 `docs/08`、`docs/37 §8`、`docs/35/34` 对应项；不得只改本文件。

以下情况一律不算闭环：
- mock / 单测 / E2E 绿，但真实外部系统没跑过；
- 只证明 “接口能通”，没证明用户能完成业务动作；
- 真实动作失败后，没有记录失败原因和恢复路径；
- 用 `unknown`、占位数据、伪造样本冒充真实数据；
- 把 “已实现代码” 写成 “已闭环”；
- 把 “本轮未跑” 写成 “通过”。

### 0.2 状态定义

| 状态 | 含义 |
| --- | --- |
| `未闭环-可本地启动` | 不依赖外部账号 / Key，今天就能从代码/本地或桌面端开始改造与验证 |
| `未闭环-待账号` | 缺真实平台账号、登录态或用户授权 |
| `未闭环-待Key/外部服务` | 缺真实模型 Key、SMTP、付费搜索等 |
| `未闭环-待部署/物理` | 缺生产服务器环境、域名/证书或真实物理机验证 |
| `进行中` | 已开始，尚未满足五条闭环标准 |
| `已闭环` | 五条标准全部满足，证据已归档 |
| `战略冻结` | 本期聚焦主干，从活跃清单与默认 UI 隐藏（有决策号 D-224），不阻塞总验收；后续按需复苏 |
| `已合并` | 核心刚需已吸收进其他活跃 RC，不再单列重复验证 |
| `已取消` | 用户明确不做，且有决策号；不算未完成 |
