## 本轮修复

1. **ST-14：重试计数不再跨阶段或跨成功检查点累积。** 原恢复逻辑读取整次操作的最大 attempt；原调度逻辑每创建一次同阶段 run 就加一。资料阶段重试成功后，目录阶段可能被提前判重试耗尽；长目录正常分批也会消耗失败次数。现在按同阶段最近一条 run 判断，只有过期才增加，成功提交检查点后从 1 开始。两个新回归测试在旧实现中分别出现“无法领取重试”和“第二个成功窗口 attempt=2”，修复后通过。
2. **ST-15：页预算耗尽可继续。** 原桌面目录终批把任何 `enumerationComplete=false` 都转换成 `catalog_inconsistent`，覆盖了适配器明确返回的 `page_budget`，服务端因此结束操作。现在由 `buildPlatformCatalogCompletion` 构造终批：仅明确页预算且确有后续页时保存 `next_page`；发布时间不明、重复页或结构不一致仍结束覆盖核对。主进程统计使用服务端回执的 accepted/rejected。
3. **ST-16：v2 已入库但响应丢失可恢复。** 原客户端直接抛错，后续 control 可能复用已经入库的批次号。现在查询同一 run/序号的持久回执，取得后才递增批次号；查询也失败则保留原错误和批次号。无新采集、无无限重试。
4. **启动目标可核对。** 启动器现在输出实际 API origin 和前端 origin。既有默认值仍是远程 API，不能用本地 `ops` 库的数据证明该远程页面状态；本轮未把本地测试结果写入真实账号。

原协议、能力开关、权限、镜像归属和每日三次 run 上限保持现有契约；无新接口和迁移。跨日测试只移动隔离测试库的历史 run 时间，不提升生产预算。原目录终批分支已替换为单个结果契约构造函数，未保留重复判断。

## 尚未覆盖及既有缺口

- “验收号-94322847988”的实际平台登录、真实作品/字段对照、远程 API 是否部署本轮代码尚未验证。测试通过不能证明该真实账号已经回显；本轮没有替换其运行中的业务服务。
- `runPlatformV2Collect` 的资料阶段仍显式返回 `profile_capability_unverified`，正文阶段仍返回 `content_capability_unverified`，并非已实现完整资料和正文读取。沿 D-133 继续验收，不能把目录可见解释成正文完整。
- 逐请求预算尚未由桌面端发送 `budget_request`，见 `server/internal/app/platform_sync_budget.go` 和 21 文档既有技术债记录。当前真正执行的每日 run 上限仍有效；本轮没有宣称逐请求账本已经接通。
- 真平台安全分页、平台结构变化、真实额度和完整历史覆盖仍需本人许可的小样本证据；不能用合成分页代替，也不承诺零遗漏或绝对无 bug。

结论：本轮自动化范围通过，已确认三类断点有定向回归；真实平台交付仍为待验收。

## 续轮：同步明细与资料自动回显（DEV-AS14）

依据 20 文档 §21.8 的既有明细设计补齐上下游，未新增平台网络读取范围、权限或数据库迁移。

- 上游既有 `.../platform-sync-operations/{operationId}/items` 补齐 `stage=content|metrics`，省略时保持原 content 行为。按阶段校验 state，返回 `initial_metrics_state`；保留账号/工作区/操作归属校验、游标与默认 20/最大 100 行限制。
- 下游设置进度新增“查看作品同步明细”，展示正文和初始指标状态、平台编号、核对时间、正文错误码；支持阶段/状态筛选、分页、刷新与读取重试。运行时定时重读，操作修订或终态变化时立即刷新。下一页失败保留已加载作品，重试原游标；切号关闭明细，查询键和取消信号绑定账号/操作/筛选。
- 资料快照跟随账号同步 id/revision/status 变化重读；进度或资料读取失败分别显示错误和重试，避免把错误当作“未同步”。网页模式未启用查询时不显示永久加载。
- 明细来自镜像的当前状态，后续操作重新处理的作品不保证仍列在旧操作中，界面已明确说明；未实现历史逐行回执查看。初始指标 complete 仅表示观测已保存，不能解释成正式指标已采用。
