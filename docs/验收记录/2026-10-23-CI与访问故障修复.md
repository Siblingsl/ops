# CI 与部署访问故障修复（DEV-AS15）

基线：`b31e164`。延续用户授权的同步上下游检测、提交部署及失败修复。

## 已定位的三处 CI 失败

- Playwright：测试从未直接声明的 `playwright` 运行时导入 `_electron`，干净 pnpm 安装无法解析；统一改从已声明的 `@playwright/test` 导入，类型引用一并统一，无新增依赖。
- 桌面模型超时：业务用真实时间计算剩余预算，测试却要求精确等于最初 25 秒。保持业务实现，测试精确验证执行截止时间，并验证 timeout 落在调用前后真实时间包围的区间内，不用任意误差或放宽门槛。
- 头条临时目录：故障夹具只设置 TMP/TEMP，在 Linux 未覆盖 os.TempDir 的 TMPDIR，导致实际下载成功。补齐 TMPDIR，并在正常/故障分支检查生效路径，保留只读、清理及磁盘故障不得返回 ZIP 的原断言。

验证：独立目录导出精确 HEAD 与本次改动；两项 Go 用例连续 5 轮通过；Playwright 完整收集 229 条/90 文件通过。全量 Go、浏览器及 Linux CI 结果待补，不由收集成功代替运行成功。

## 访问诊断边界

本地直连 HTTP 返回 403、HTTPS 连接超时；不据此认定是应用代码错误。现有 Deploy workflow 增加手动 `diagnose` 模式，通过原部署 SSH 通道只读检查容器、Nginx、监听端口、公有证书及本机/公网健康请求，不运行更新、不读取秘密文件内容；默认 deploy 行为保持。云备案/端口/证书配置及外部访问结果待远程证据确认。
