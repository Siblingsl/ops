## 1. 已确认范围与成功标准

### 1.1 用户确认记录

| 编号 | 确认事项 | 结果 |
| --- | --- | --- |
| TT-Q01 | 内容形态 | 文章＋微头条；视频、漫画不是首版目标 |
| TT-Q02 | 发布方式 | 系统完成创作与发布包，用户手动到头条发布，再人工回填 |
| TT-Q03 | 现有接入资源 | 当前没有头条号，没有已有应用、接口权限或合作渠道 |
| TT-Q04 | 跨平台派生 | 公众号长文、小红书图文笔记可逐篇派生为头条文章或微头条；头条文章可派生到公众号长文或小红书图文笔记；微头条向长文扩写后置 |
| TT-Q05 | 数据回收 | 手动录入＋粘贴／CSV 导入＋截图识别后人工确认；自动读取后台和收益统计后置 |

### 1.2 可观察的成功标准

1. 不配置头条密钥也能建立系统账号、建档、选题、创作两种形态、逐项检查、生成与下载发布包。
2. 同一个账号下，两种形态有独立作品，分别进入正确编辑器、检查规则、发布包和复盘分组；不会因为改变默认形态修改历史作品。
3. 仅开放 TT-Q04 确认的派生路径，逐篇创建目标稿并保留来源；模型不能编造源稿没有的事实。
4. 打包只表示本地交付物准备完成。打开头条后台、等待平台审核、页面跳转或解析到链接，都不自动标记已发布。
5. 已发布作品能录入和确认导入表现数据，展现与阅读不混用，空值不当作零，文章与微头条不混为同一类写作偏好。
6. 公众号和小红书原有功能、H-01 至 H-09、HC-01 至 HC-31 保持有效。D-127 的采集技术口径不因新增平台被恢复为技术手段禁令。

## 2. 可行性、方案比较与外部事实

### 2.1 结论与方案

技术上可行。现有系统已有账号隔离、作品级形态快照、分段创作、检查、发布包、回填和多来源指标，可增量复用。真正需要新增的是第三个平台的显式分流、微头条表达、同账号多形态入口、头条发布包和指标适配。

| 方案 | 前提与代价 | 本次结论 |
| --- | --- | --- |
| 发布包＋人工发布 | 无需头条 API 权限；用户负责登录、排版复核、声明与最后发布 | **用户已选择，作为首版主路径** |
| 客户端辅助填入 | 需另验登录态、页面结构、图片上传、失效恢复和客户端信任边界，维护面更大 | 后续候选，不进入首版，不把它写成技术禁令 |
| 官方接口／合作接入 | 需先取得对应体裁和账号的有效权限，再验证授权、审核、额度与撤销 | 未取得资源，不作为首版依赖；视频权限不能代替图文权限 |

不为未来可能获得的接口预建 OAuth、凭证表或通用插件框架。未来真实能力成立时，再按当时契约补充设计。

## 4. 账号、作品形态与创建规则

### 4.1 标识与职责

| 对象 | 设计 |
| --- | --- |
| 平台枚举 | 新增 toutiao；显示“今日头条”，空间较小时可显示“头条” |
| 文章形态 | 复用 long_article；具体编辑、检查、交付由“平台＋形态”决定 |
| 微头条形态 | 新增 micro_post；不复用 image_note，也不伪装成卡片或口播脚本 |
| 账号默认形态 | 仍使用 platform_account.content_format；头条创建默认 long_article，可选 micro_post |
| 作品实际形态 | work.content_format 是权威快照，创建后不可直接 PATCH 改形态 |
| 账号定位与素材 | 同一 account_id，共享定位、人设、风格样本和账号素材；工作区共享素材沿现有可见范围 |
| 凭证状态 | 头条显示“人工发布，无需配置接口凭证”，不显示“凭证异常”，不要求 AppID／AppSecret |

开发前基线为 8 个唯一形态、11 个平台×形态组合；头条实现增加 micro_post 及两种头条组合后，共 9 个唯一形态、13 个组合，原两平台组合保留。

### 4.2 统一解析规则

头条账号新增作品时，按以下顺序决定形态，并写入快照：

1. 从选题、推荐或计划槽位开写：已有来源形态优先。若请求另带不同形态，拒绝并提示先修改该来源，不静默覆盖。
2. 无来源的手动新建或派生：使用用户明确选择的 content_format。
3. 没有明确选择且来源也无形态时：使用账号当前默认形态。
4. 结果必须是 formatMatrix[toutiao] 中的 long_article 或 micro_post；未知值和其他平台的形态返回 422。

合法性、创建解析和派生矩阵分别由后端集中维护，不能在每个入口各写一份 if。前端清单、客户端设置和智能体 Schema 必须与后端矩阵做契约一致性验证；首版不新增类型管理平台或通用插件注册系统。

**D-048／D-123 的范围调整只限头条**：公众号和小红书继续要求新作品形态等于账号当前类型；头条允许在其支持的两种形态之间逐篇选择。旧平台迁移后采用旧推荐／槽位的拒绝行为与测试保持。

### 4.3 选题、推荐、计划与默认形态修改

- 头条选题的 format 可空或为两种合法形态。手动编辑选题可修改预计形态；已有作品不随选题修改。
- AI 选题表单提供“本次形态”，默认取账号默认值；生成请求明确传入形态，模型返回其他形态须纠正或按既有无效输出流程失败。
- 热点发现、RSS、收件箱、手动素材与带来源的模型联网搜索复用现有能力及工作区运行配置。已有“头条热榜来源”与本次“头条运营账号”是不同对象，不重复建热榜适配器，不将热点接入等同于已能读取账号后台。
- 首版每日推荐和新运营方案按账号默认形态生成，**不新增混合比例排期**。推荐、槽位保存各自形态；采用时验证它仍属于头条支持集合，而非必须等于当前默认值。
- 没有作品上下文的生成任务，也必须显式携带本次目标形态；不能只靠账号默认值推测一条已选微头条选题。
- “修改类型”在头条账号上显示为“修改默认创作形态”，沿用 D-123 的显式确认请求和审计。说明默认值影响未来无明确选择的入口，不改已有作品、选题、推荐和槽位。
- 新建作品成功后显示实际形态；返回列表、工作台、待回填、日历和复盘逐行标注。账号层仍是一个账号，不拆成两份运营数据。

## 5. 创作、配图与人工确认

### 5.1 文章

复用现有长文分段编辑器、自动保存、版本记录、观点、大纲、逐段起草、标题备选、图片库、替代文字与素材引用。文章结构用段落、小标题、列表、引用和基础加粗表达；不套用公众号主题和微信 HTML 大小规则。

不强制生成公众号摘要、填写微信作者／阅读原文／留言设置，不要求微信封面双裁剪。首版封面由用户到头条后台选择；正文配图随包导出，不为尚未核验的封面模式新增持久化字段或虚构必填检查。

### 5.2 微头条

- work.title 用作**内部名称**，便于列表、搜索和数据匹配；界面明确“仅系统内使用”，不作为发布标题输出。
- 正文仍存 work_section，首版用 1–3 个短要点作为建议大纲，允许人工调整数量；需要本人观点和 H-03，随后逐段起草、编辑与确认。
- 发布正文由有效段落按顺序拼接；不输出段落小标题或内部名称。预览、计数、复制和下载使用同一转换结果。
- 图片为可选。支持无图纯文字作品，不继承小红书“至少 1 张图”的要求；上传、排序、删除使用现有资产能力。
- 话题使用既有 work.topics，单独显示与复制；正文中已经出现的同名话题在合并复制时不重复插入。提示在头条话题选择器中确认，不能保证纯文本 #话题 已关联活动。
- “标题备选”显示为“内部名称备选”，生成结果不写正文。首句优化使用现有段落改写路径和卡片，不新增隐式插入正文的按钮。

### 5.3 共同规则

H-01 选题逐条采用、H-02 本人观点、H-03 大纲确认、H-04 检查逐项处理、H-06 平台人工发布、H-07 人工回填、H-08 复盘建议逐条采纳、可选 H-09 审阅全部适用。H-05 原本指公众号草稿写入，头条不制造一个外部写入动作来套用它；包准备属于已有发布衔接中的人工单篇操作。

已发布作品默认锁定；解锁只修改系统记录，不修改头条后台。版本恢复继续使用 D-122 的结构与依赖校验，不能把文章版本恢复成微头条，也不能恢复旧检查或审阅通过凭据。

AI 上下文以“平台＋本作品／本次目标形态”为准，分别说明文章的论述结构、微头条的短内容表达。统一排除无权访问、已删除或过期的素材，模型不将外部文本中的指令当系统指令，不承诺流量和原创权益。

### 7.1 用户流程

  B --> C[观点与大纲确认]

复用 drafting → checking → reviewing（可选）→ ready → packed → published；不新增“头条已同步”“平台已审核”等状态。头条不会进入 pushed。平台审核中或结果未知时保留 packed，页面提示核对真实状态；不解析审核成功来自动推进。

### 7.2 发布包结构与转换

| 文件 | 文章包 | 微头条包 |
| --- | --- | --- |
| title.txt | 仅发布标题 | 不生成，内部名称只记录在清单中 |
| body.txt | 基础纯文本正文 | 不含内部名称、小标题的发布正文 |
| article.html | 简洁、安全的离线文章预览，图片使用包内相对路径 | 不生成 |
| topics.txt | 为空或记录用户手动整理的待核对话题 | 话题列表，不默认混入 body.txt |
| images/01.jpg 等 | 实际引用的正文图片，保留去重后的确定顺序 | 用户选择的图片顺序；无图时可无该目录 |
| image-map.json | 图片文件与段落位置的对应，重复引用同图可列多个位置 | 图片有序清单，不承诺正文插图位置 |
| manifest.json | 版本化交付清单与文件校验信息 | 同左 |
| 发布说明.txt | 上传、排版、封面、声明、人工发布及回填步骤 | 上传顺序、话题确认、声明、人工发布及回填步骤 |

图片按现有资产的真实编码决定扩展名，不对 PNG 字节直接改名为 JPG。仅打包当前作品实际选择／引用的图片，不把整个账号图片库全部导出；跨作品、缺失、损坏文件均报错。

文章按有效段落顺序解析正文图片引用，映射为当前 work_id 的合法 asset.id，按首次出现顺序编号；同一 asset 多次引用仅导出一份文件，并记录全部位置。上传但未插入文章的图片不作为已使用正文图，包页提示其未导出。微头条以本作品有效资产的 position、id 稳定排序作为所选图片顺序，不解析正文插图位置。外链图片尚未保存为合法作品资产时，提示先上传／选择，不在打包时临时下载远程文件。

image-map.json 的文章项为 asset_id、file、uses（section_id、段内图片序号 ordinal、alt）；微头条项为 asset_id、file、position。图片只在 article.html 和位置说明中出现，body.txt 不写私有 URL、Markdown 图片语法或会被误发为正文的图片占位文案。已有 AI 标识在图片处理和导出中保留，压缩／转码造成的标识丢失也须纳入 SP-TT02 核对。

文章转换允许段落、小标题、加粗、基础列表、引用和安全 http/https 链接；去除脚本、事件、iframe、样式注入及危险协议。代码、表格降为可读纯文本并产生降级提醒。微头条去除 Markdown 格式语法，保留实际文字、换行、表情和显式话题；图片从正文剥离到有序列表。

网页“复制文章正文”默认复制纯文本，可另提供“复制基础格式”；复制内容均不含私有图片 URL。不能承诺将受 Cookie 保护的系统图片直接粘贴到头条；图片由用户单独上传，位置参照 image-map.json。article.html 仅用于解压后离线参照，不等于头条支持导入 HTML。浏览器剪贴板拒绝时保留可选文本区供人工复制。

manifest.json 的最小契约：schema_version=1、platform、content_format、work_id、basis_revision、generated_at、标题／内部名称、正文与话题文件名、按顺序排列的图片、图片位置映射，以及各交付文件的 SHA-256。文件哈希不包含 manifest 自身，避免自引用；路径由系统生成，禁止标题或外部文件名形成目录穿越。

### 7.3 一致性与失败处理

1. 页面记录所见 work.revision。准备、读取包视图和下载均传 basis_revision；新头条接口缺少基准返回 422，过期返回 409，不把旧页面静默升级为最新包。
2. 服务端通过一致性视图读取同一作品、有效段落、话题、图片与引用顺序，验证当前 H-04／H-09 和素材依据，组装不可变的本次输入。
3. 准备接口读取并校验必需文件、完成文字转换后，再在短事务中复核修订、权限、状态及素材依据；只有成功才将 ready 更新为 packed 并返回包视图。文件读取和压缩不持有长数据库事务。
4. 下载先完整构建临时 ZIP、校验错误、关闭 ZIP，再复核作品修订、当前权限和素材依据；通过后才发送响应头和二进制，临时文件按现有退出清理方式删除。构建失败不能返回部分 ZIP。
5. 这保证包内来自同一修订并在最后检查时仍有效，不承诺跨数据库、文件系统和传输的分布式原子性。校验后客户端若离线或稿件再次变化，已取得的包仍是旧修订，必须按页面标注核对。
6. prepared／packed 不代表长期归档或历史交付。首次准备 packed，重复准备同修订不制造额外发布事实；已发布作品不被包操作退回 packed。
7. GET 读取和 ZIP 下载不改业务状态；服务器重启不丢失作品，不依赖内存保存包。导出旧稿时明确这是“当前系统内容”，不冒充当时实际发布快照。

不建头条交付历史表、publication_event 或长期 ZIP 存储，不把发布包写入公众号 push_record。复用 D-122 的本次修订与文件完整性机制，只提取两平台实际共用的底层构件。

### 7.4 人工发布与回填

发布包页提供“打开头条号后台”外链、复制、下载和“回填已发布”；外链使用官方 HTTPS 地址，由用户登录。无头条账号时提示先按官方流程注册，系统账号本身不声称已经绑定或验证头条身份。

回填沿用 POST /works/{id}/published，用户确认 H-07 后填写实际发布时间，链接可空。发布时间不晚于当前时间，上海时区展示；平台审核期间不填写猜测时间。

链接保存沿既有 http/https、长度和无用户名密码校验。头条完整文章链接和分享链接的识别规则另按 V-028 验证；**解析失败仍可人工录入，不阻止合法 URL 保存**，不把打开链接当作发布证明，不新增“必须在线抓取验证链接”的依赖。

更正沿 D-122 使用 mode=correction、base_publish_revision、原因、预览和原子节点重算，冲突时保留表单重新比对。只更正系统记录，不同步修改、删除或撤回平台内容。

## 8. 跨平台派生与首发提醒

### 8.1 允许矩阵

每个单元格都表示“逐篇创建独立目标作品”，不是复制后自动发布。

| 来源 | 目标 | 首版 |
| --- | --- | --- |
| 公众号 long_article | 头条 long_article | 支持，保留论述，调整开头与平台表达 |
| 公众号 long_article | 头条 micro_post | 支持，压缩为一个清晰观点，保留事实出处 |
| 小红书 image_note | 头条 long_article | 支持，展开已有要点，缺事实时提示补素材 |
| 小红书 image_note | 头条 micro_post | 支持，整理短正文，不继承小红书专属引导语 |
| 头条 long_article | 公众号 long_article | 支持，适配公众号表达与后续排版 |
| 头条 long_article | 小红书 image_note | 支持，压缩为笔记，另行选图与检查 |
| 头条 micro_post | 任意其他平台长文／笔记 | 后置，不允许通过通用文字类型判断误放行 |
| 头条任意形态 | 同平台任意形态 | 首版不做，保持跨平台派生边界 |
| 旧平台既有长文↔笔记、漫画↔漫画 | 原有目标 | 沿现有规则保持 |
| qa_article、briefing、list_note、card_post、script 或漫画 | 头条任意形态 | 首版不支持，不因平台新增扩大转换矩阵 |

目标是头条时必须在派生入口明确选形态；目标为旧平台时仍取目标账号当前类型，并验证确为矩阵允许的类型。未知／不支持路径在调用模型前返回 422。

### 8.2 创建、引用与事实

复用 source_work_id、source_revision、source_section_ids 和 source_revisions，保留单篇对照与源稿更新提醒。多个源段落可对应一个短段落，不强求微头条与长文段数相同。

目标稿有独立检查、审阅、回填和数据，源稿修改不静默覆盖目标稿。派生不得继承“已检查”“已审阅”“已发布”状态。沿用当前派生已有的观点／大纲确认契约，不借新增路径放宽 H-02／H-03；后续对照改写仍逐段执行。

仅复制目标账号有权引用的工作区共享或目标账号素材关系，源账号私有素材不直接授权给目标稿。源稿含目标不可见的资料或来源时，给出通用缺依据提示；不得把不可见素材原文作为工具结果暴露。图片首版不跨作品自动引用，目标稿通过已有图片库选择／上传得到合法资产后再打包。

### 8.3 首发、原创与 AI 声明

三项不是同一开关。首版不在系统里保存“已替平台声明原创／首发”的布尔值，也不自动打勾。发布包固定提醒按真实创作情况处理 AI 声明、核实原创条件、首发默认不选。

若作品家族中已有其他平台发布记录，头条包显示“存在其他平台已发布记录，请勿直接声明头条首发”。如用户在头条自行选择首发，提示 F-406 的 72 小时要求，由用户安排其他平台实际发布时间；不禁止继续写稿或派生，不创建自动发布排队任务。

系统不知道用户在站外的全部历史发布，不能根据“系统中没有记录”判定符合首发，也不承诺改写后即可规避首发约束。收益、原创权益、AI 辅助边界的实际资格均以平台当前规则和审核为准。

## 9. 数据回收、指标与复盘

### 9.1 指标契约

| 字段 | 说明 | 存储与展示 |
| --- | --- | --- |
| impressions（新增） | 展现量 | 可空非负整数；与 reads 分开 |
| reads | 阅读量 | 沿用现有字段，不接收展现量的别名 |
| likes、favorites、comments、shares | 点赞、收藏、评论、分享 | 当前体裁后台确实显示时录入；不存在则空 |
| follows_gained | 单篇作品新增关注 | 仅有明确单篇口径时填写，账号粉丝净变化不能代填 |
| ctr（派生） | 同一快照 reads / impressions | 分母大于 0 且两者均有值时计算；接口返回比率（例如 0.2），界面显示百分比，不截断异常比例 |
| captured_at、source、day_offset、revision | 观察时间、来源、发布后节点、数据修订 | 沿 DR01／D-122，不另建头条指标权威表 |

不采集收益、私信、粉丝画像，不把 wows（公众号在看）展示为头条字段。阅读完成率、时长、粉丝展现／阅读后置，不能随意塞进备注后声称已参与统计。

首版快照只接收截至 captured_at 的累计作品数据。截图中“昨日／某日／近七日”这类区间指标先提示切到累计视图或明确整理为累计值，不把区间数直接写成生命周期累计。V-027 用真实后台样本确认各体裁含义与展示字段。

0 与 NULL 分别保留。展现为 0 或任一值缺失时 CTR 为 NULL，不返回 0%；同一来源同一节点按既有合并规则补已知值，不把缺失字段清零。不同来源的分子分母不拼接。reads 大于 impressions 或累计数下降给出可核对的软提示，不以猜测修正原数。

### 9.2 录入、粘贴与截图

- 手动单篇录入沿原入口，新增展现输入和只读 CTR。修正／删除携带 base_revision，冲突返回 409，保留输入和前后审计。
- 粘贴／CSV 沿原预览与确认入口，增加“展现量／展现／impressions”精确别名；不得将“曝光／阅读／播放”无差别合并。新头条导入推荐带 work_id，或提供完整发布 URL、形态、日期和标题用于辅助选择。
- 微头条没有可靠外部标题。截图／CSV 允许 title 为空；用户在本账号作品中选择匹配项。标题完全相同、日期或形态冲突、多个候选时保持未匹配，不取最新一条自动写入。
- 匹配优先为当前账号合法 work_id，其次为已保存且规范化后明确相同的完整 URL；其余显示候选供人选择。所带形态、发布日期或 URL 与目标作品事实冲突时阻止确认并提示核对，不通过导入暗改作品发布时间。未核实短链不通过网络猜测归属；不匹配跨工作区、跨账号作品。
- 识别任务 metric_screenshot 复用现有视觉模型路由。头条上下文带候选作品 ID、内部名称、形态和日期；按截图原样输出数字及 raw_text，程序换算“万／亿”，看不清或不存在的字段留空。
- “10万+”属于下界近似，按既有预览近似提示处理；未明确确认前不冒充精确值。截图只提供匹配建议，用户逐行确认后写 source=screenshot。

示例 CSV 契约（仅说明列名；UUID 为虚构示例）：

~~~csv
work_id,content_format,published_at,captured_at,impressions,reads,likes,comments
11111111-1111-4111-8111-111111111111,long_article,2026-10-18T10:00:00+08:00,2026-10-20T10:00:00+08:00,1000,200,8,2
~~~

请求中的 source 不由模型任意指定，按真实入口决定；写入前再次校验匹配归属、数值与作品状态。来源优先级和节点选择沿 work_metric_d7 原规则，本次不另发明“头条优先”的来源排序。

### 9.3 混合形态账号的复盘

账号总览可以展示总作品数等总量，但平均阅读、互动率、高表现样本和写作偏好必须按 work.content_format 分组；跨平台也不做直接流量排名。默认先显示当前选择的形态，并提供文章／微头条切换。

高表现样本查询在取样前限制同一账号和目标形态。归因先按现有有界窗口取最近最多 500 篇，再分形态统计；不扩大为每个形态各 500 篇。数据不足时提示样本不足，不借另一形态凑样本，不把累计第 1 天与第 30 天当同等第 7 天数据。

确定性偏好复用 account_data_preference：头条的 feature 使用 long_article:原特征 或 micro_post:原特征的命名空间，basis_meta 增加 content_format；仍由当前账号的输入修订控制适用性。一次账号重算同时计算两个形态，CAS 成功后才推进 pref_processed_revision；不能处理完一种就把另一种旧结果标为有效。旧平台 feature 和查询语义不改。

生成提示只注入同目标形态、依据有效的偏好及样本；头条缺少形态元数据的记录视为不可用于注入。现有样本数和差异阈值不降低。impressions 首版只用于看板和复盘展示，不新增“按 CTR 自动学习”规则；只改展现数需推进指标 revision，但不假装改变了仅依赖阅读／互动的统计偏好输入。

AI 复盘必须看到形态、数据来源、观察日期及节点口径，不能据缺失展现推算推荐量，也不能将文章结论直接应用于微头条。复盘建议仍经 H-08 逐条采纳。

### 11.1 通用约定与既有接口增量

| 方法与路径 | 增量或约定 | 权限 |

### 11.2 新增头条发布包接口

| 方法与路径 | 输入 | 输出与行为 |
| --- | --- | --- |
| POST /works/{id}/toutiao/pack | body：basis_revision，必填正整数 | 完成第 7.3 节准备；成功返回包视图并将 ready 推进 packed；已 published 不降级 |
| GET /works/{id}/toutiao/pack | query：basis_revision，必填 | 读取当前包视图，要求 packed／published 及当前依赖有效，不修改状态 |
| GET /works/{id}/toutiao/pack.zip | query：basis_revision，必填 | 完整 ZIP，头 X-OPS-Basis-Revision；临时文件构建／最终校验成功后才发送 |

POST 为 owner／editor，GET 沿既有包读取的 viewer 权限，不新增扩大可见范围的匿名下载。所有端点先验证 work 归属、平台为 toutiao、形态合法；不能经 xhs 包接口访问头条作品，反向亦然。

包视图最小响应示例：

~~~json
{
  "work_id": "11111111-1111-4111-8111-111111111111",
  "platform": "toutiao",
  "content_format": "micro_post",
  "basis_revision": 12,
  "internal_title": "周末阅读的三点体会",
  "publish_title": null,
  "body_text": "周末读书时，我发现先写下自己的问题，更容易记住有用的内容。",
  "topics": ["阅读"],
  "images": [],
  "warnings": ["发布时请核对 AI 声明；头条首发默认不选。"]
}
~~~

文章 publish_title 为实际标题，micro_post 为 null。图片条目使用系统内可访问的预览地址、确定的导出文件名与排序；响应地址不写入离线正文。文本长度统计从响应同一正文结果产生，不能各端自行剥离 Markdown 后算出不同数字。

错误沿用：401 unauthenticated；403 权限／CSRF；404 not_found（含跨工作区不可见）；422 validation_failed（非法平台、形态或缺基准）；409 version_conflict／state_invalid／human_step_required。缺图或文件损坏可用 422 并给结构化缺项与中文修复入口；存储 I/O 故障用既有服务器错误。失败不推进 packed，不伪造成功审计。

### 12.3 头条匿名分享预览（2026-10-20 用户补充确认）

用户明确选择补齐现有 24 小时匿名分享能力。入口位于已生成发布包的页面，生成前说明“持有链接即可匿名读取”；不自动创建链接、不自动发送给他人，也不改变发布状态。分享链接复用现有签名与有效期机制，无需新增公开作品表。

文章只分享发布标题、基础格式正文、话题及正文实际引用的图片；微头条只分享发布正文、话题和有序图片，不返回内部名称、段落小标题、素材依据、检查详情或其他系统字段。匿名页面明确显示“今日头条 · 文章／微头条”和“内容预览，不代表平台已发布”。不复用公众号主题渲染。

头条链接绑定作品修订。每次匿名读取正文或图片都复核该修订、作品归属、发布包状态和素材依据；改稿后旧链接失效，不能静默展示新内容。过期、作品删除、图片不属于当前交付内容或依赖失效均不返回正文／图片；拒绝跨作品取图。沿用 `no-store` 与 `no-referrer`，分享链接只在本人操作后展示与复制，智能体不读取 token。

生成头条分享链接的 `POST /works/{id}/preview-link` 请求必须包含正整数 `basis_revision`，与用户看到并确认的发布包修订一致；缺失或无效返回 422，期间改稿并重新打包仍须拒绝旧修订并返回 409，不能静默改为当前版本。页面提供“刷新作品”入口；智能体由提出卡片时的服务端作品读取冻结修订，执行时不重新填入新值。公众号原无请求体调用保持兼容。
