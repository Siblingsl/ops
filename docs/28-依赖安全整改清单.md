## 2. 逐条评估

### 2.1 chi：客户端 IP 可伪造（server，直接依赖）

**漏洞**：`ClientIPFromXFF` 直接信任 `X-Forwarded-For`，攻击者可伪造客户端 IP（CVSS 4.8）。

**仓库现状**
- `server/internal/app/server.go:137` 使用 `middleware.RealIP`（同类信任逻辑）。
- `server/internal/app/httpx.go:179` 有自研 `clientIP()`，同样取 XFF 第一段。
- `clientIP()` 的消费方：`auth.go` 的 `audit(...)`（登录成功/失败）与 `session` 记录的登录 IP。
- 部署侧 `deploy/nginx-ops.conf`、`deploy/nginx-ops-https.conf` 都设置了 `X-Forwarded-For $proxy_add_x_forwarded_for`。

**判断**：升级 chi 只能关掉它自己的 helper；**本仓库的 `clientIP()` 一字未改，伪造 IP 依然成立**（已于 P4 修复，见下方建议动作 2）。影响面是审计日志与登录 IP 失真（不是提权）。若将来接限流/风控，这会变成绕过手段。

**建议动作**
1. ~~`cd server && go get github.com/go-chi/chi/v5@v5.5.0 && go mod tidy`。~~ **已做（2026-11-09，`0863e126`）**：`go.mod`/`go.sum` 仅 chi 一项变化；`go build ./...`、`go vet ./internal/app ./internal/ai ./cmd/...`、定向路由回归通过。
2. ~~另立一项（与升级解耦）：仅在显式配置可信代理（如 `OPS_TRUSTED_PROXIES` CIDR）时采信 XFF，否则用 `RemoteAddr`；`clientIP()` 与 `middleware.RealIP` 二选一，不要两套并存。~~ **已做（P4，2026-11-09）**：新增 `internal/app/client_ip.go`，未配置时不采信 XFF；配置后从右往左取第一个非可信地址（对齐 Nginx `$proxy_add_x_forwarded_for` 的写入顺序）。**执行中发现更前置的问题：`middleware.RealIP` 会先把 `r.RemoteAddr` 改写成 XFF 第一段，使 `clientIP()` 内部的任何可信判断都被架空，已一并从 `buildRouter()` 移除**（详见 docs/90 D-173）。
3. 若后续改用 chi 的 `ClientIPFromXFF`，必须传可信代理参数（新版签名要求）。

**验证**：`go build ./... && go vet ./internal/app ./cmd/...`；~~手工构造带 `X-Forwarded-For: 1.2.3.4` 的登录请求~~ **已固化为自动化用例** `TestLoginAuditIgnoresForwardedForThroughFullRouter`（伪造 XFF 登录后回查 `audit_log.detail->>'ip'`，须为回环地址）。该用例已用「临时加回 `middleware.RealIP`」反向验证过会变红（ip 被写成 1.2.3.4），不是假守卫。

**代价**：低（minor，无 API 删除）。**风险**：低。

### 2.2 react-router：开放重定向（两端，传递依赖，有真实接触面）

**两条 advisory**
- `GHSA-wrjc-x8rr-h8h6`：`<Link>` / `useNavigate` 通过**反斜杠**实现开放重定向，是 CVE-2025-68470 的绕过（CVE-2026-53669）。
- `GHSA-337j-9hxr-rhxg`：SSR hydration 的 `deserializeErrors()` 任意构造函数注入（CVSS 6.1）。

**仓库现状**
- 两端均锁 `react-router-dom@6.30.6`（6.x 最新版，**该线无修复**）。
- 无 SSR：`web/src` 与 `desktop/renderer-src/src` 中不存在 `hydrateRoot` / `deserializeErrors` / `StaticRouter` → **第二条不适用**。
- 第一条**不是纯理论**：`web/src/lib/agent-markdown.tsx:59` 的守卫是
  `href.startsWith('/') && !href.startsWith('//')`，**没有拦反斜杠**；`href` 来自模型输出的 Markdown，随后 `navigate(href)`。`/\evil.com` 这类值能通过该守卫，在 6.30.6 上可能被当成外站跳转。
- 桌面端同一份代码（`desktop/renderer-src/src/lib/agent-markdown.tsx:59`）。

**建议动作**
1. ~~**先做（不依赖升级）**：把内部链接判定改为「必须是 `/` 开头、第二个字符不是 `/` 或 `\`、不含控制字符」，并在 `safeHref()` 做同样限制；补一条单测覆盖 `/\evil.com`、`//evil.com`、`/%5Cevil.com`。~~ **已做（2026-11-09，`2d193a6c`）**：两端新增 `lib/internal-link.ts`，拒绝 `//`、任意反斜杠、控制字符、首尾空白、超长与前 16 字符内的 `%5C`/`%2F%2F`；两端各 3 条测试（19 条拒绝 + 5 条放行 + 接线断言）。
2. **再升级**：`react-router-dom` `6.30.6 → 7.18.x`（≥7.18.0）。v7 中 `react-router-dom` 仍可作为兼容入口，但官方建议逐步改用 `react-router` 的导出。
3. 升级后回归全部路由（两端各 466 处 `Link`/`navigate` 调用），重点：登录跳转 `?next=`、工作台深链、桌面端 hash/history 差异。

**验证**：两端 `typecheck` + `test:unit` + `build`；E2E 全量；手工构造带 `/\` 的模型输出链接，确认不再弹出站外。

**代价**：中高（major + 全站路由回归）。**风险**：中。

### 2.3 @tiptap/core：`mergeAttributes()` 原型污染（两端，传递依赖）

**漏洞**：`mergeAttributes()` 把自有 `__proto__` 键转成继承的可执行 DOM 属性（GHSA-cp6q-959q-f8rh，无 CVE，CVSS 未评分）。

**仓库现状**
- 两端锁 `@tiptap/* 2.27.3`。
- 唯一使用点：`web/src/components/section-editor.tsx:201`，扩展固定为
  `StarterKit / Link / AssetImage / Placeholder / Markdown`，且 `Markdown.configure({ html: false })`。
- 全仓库未见把**外部可控属性**传给 `mergeAttributes` 的自定义扩展；内容以 Markdown 文本进入编辑器，不解析 HTML。

**判断**：当前暴露面低（需要恶意扩展或把不可信属性塞进 schema）。但 2.x 无修复版，会长期挂在告警里。

**建议动作**
1. ~~升级 `@tiptap/core` 及同族到 `≥3.30.4`，两端同时升~~ **已做（P3，2026-11-09）**：两端统一到 `3.33.0`，`tiptap-markdown` 升 `0.9.0`（其 peer 已声明 `@tiptap/core: ^3.0.1`，是清单原先担心的卡点，实际已官方支持）。
2. ~~3.x 属大版本，需按官方迁移说明核对~~ **核对结果见下方「实际改动」**。
3. 升级前不要改 `html:false`，这是当前最主要的缓解措施。**已保持不动**。

**实际改动（与预估的差异）**
- `tiptap-markdown` 不是卡点；真正卡住的是三处运行时行为，`typecheck` 只拦住了其中两处：
  1. `BubbleMenu` 从 `@tiptap/react` 移到 `@tiptap/react/menus`，且 `@tiptap/extension-bubble-menu` 变成**需要显式安装**的可选 peer；
  2. 同一组件的 `tippyOptions` 改名 `options`（实现从 tippy.js 换成 Floating UI）；
  3. **`useEditor` 的 `shouldRerenderOnTransaction` 默认值变为 `false`（该选项已标 legacy）**——事务不再触发重渲染，toolbar 的 `editor.isActive()` 激活态会永远停在初始值。这一条 typecheck 查不出来，是 E2E 抓到的。已改用 `useEditorState` 订阅，而不是打开那个注定被移除的开关。
- 另有两处需显式保持旧语义：`setContent` 第二参数由 `boolean` 改为 `SetContentOptions`，且 `emitUpdate` 默认值从 `false` 变为 `true`，因此两处调用都写明 `{ emitUpdate: false }`，否则 `setMarkdown` 会重复触发 `onChange`。
- `StarterKit` 3 已内置 `link`/`underline`，保留独立的 `Link.configure(...)` 时必须 `link: false`，否则重复扩展。

**验证**：两端 `typecheck` 0 错、`test:unit` 48/48 与 44/44、`build` 通过；web E2E 21 例、desktop E2E 8 例通过，其中新增 `sec-tiptap3-bubble-menu.spec.ts`（双端各一份）专测气泡菜单的出现、定位与收起，并已确认它能抓住 `desktop-editor-restoration.spec.ts` 里 toolbar 激活态的回归。

**代价**：中（major）。**风险**：中，已通过上述三处运行时修正收口。
