# 14 数据回收闭环规划

> 版本：v0.2（已确认，2026-10-11；见 D-051）
> 范围：作品发布后的表现数据（阅读、点赞、收藏等）怎么进系统、怎么保证准确、怎么自动用于复盘和推荐。
> 关联：04 文档 FR-M11-01 至 FR-M11-05；12 文档 DEV-U106（粘贴回填）；13 文档（数据回流到生成端）；决策 D-003、D-005、D-010、D-047、H-07、UX-03；核验 F-008、F-101、F-306、V-006、V-011。
> 本文只做分析和方案，开发以确认后的任务编号（第 9 节）为准。

---

## 0. 结论

1. **"全自动"做不到，原因在平台，不在代码。** 小红书没有创作者数据接口（F-101），笔记页 robots 禁止读取（F-306）；公众号数据统计接口要求认证（F-008），而当前账号是未认证的个人主体，且已决定不升级（D-003、D-005、D-010）。在红线内（不用登录态、不做浏览器自动化、不逆向创作者后台接口），**你自己的两个账号目前都拿不到可自动拉取的数据源**。
2. **能做的是把"人工提供数据"的成本降到每篇十几秒**，然后让后面的分析全部自动：
   - 小红书和公众号都主推**截图识别**：发布 1、3、7 天后系统提醒，用户在手机上截一张数据页上传，模型识别出数字，人看一眼点确认；作品列表页截图可一次识别多篇；
   - ~~导出文件模板~~：已实地核验，两个平台后台都没有"导出数据"按钮（V-006、V-011，2026-10-11），此项取消；
   - 公众号接口同步保留给认证账号（以后可能用到的协作者账号），并修复现有实现的几个数据错误。
3. **数据进来之后的闭环可以自动化**：统一按"发布后第 N 天"对齐口径、自动算规则统计、自动生成每周复盘草稿、把表现结论回流到选题推荐。**只有"采纳复盘建议"保留人工**——这是 UX-03 的设计，不是能力不足。
4. **现有公众号同步有 4 个需要先修的数据问题**（第 1.2 节），无论后续方案怎么定，都应先修。

## 2. 目标与边界

**目标**：

- 每篇作品在发布后第 1、3、7 天各有一条可信数据，第 30 天可选；
- 人工操作每篇每个节点不超过 15 秒（截图识别）；多篇一起补时，一张作品列表页截图覆盖多篇；
- 数据进来之后，统计、复盘草稿、推荐回流全部自动，人只做判断和采纳。

**不变的规则**：

- H-07：发布状态仍由人回填，系统不自动判定"已发布"；
- UX-03：复盘结论和建议只是草稿，人逐条采纳；
- HC-06：不调用 `freepublish` 等发表、群发接口（所以也不能用"已发表列表"接口来找文章）。

**明确不做**（红线或不划算）：

| 不做 | 原因 |
| --- | --- |
| 用 Cookie 或登录态调用小红书创作服务平台、公众号后台的网页接口 | 红线：不使用账号登录态、不逆向接口 |
| 浏览器插件或 RPA 读取已登录的后台页面 | 红线：浏览器自动化 + 登录态 |
| 爬取作品公开页面拿互动数 | robots 禁止（F-306、F-307） |
| 第三方数据平台（新榜、千瓜等）抓取 | 只提供公开数据，且多为抓取所得，合规不可控；如果以后要用，只接其官方付费 API，另开决策 |

## 4. 各层方案

### 4.1 E 数据质量（EX-DR-01）

1. `metric_snapshot` 增加字段：
   - `source`：`manual` / `paste` / `file` / `wechat_api` / `screenshot`；
   - `day_offset`：发布后第几天（由 `captured_at - published_at` 计算，入库时写死）；
   - `external_id`：接口来源的文章编号（公众号 `msgid`），可空；
   - 唯一键：`(work_id, source, day_offset)`，同一来源同一节点再次写入时更新而不是新增。
2. 接口没有提供的字段写 `NULL`，界面显示"—"，统计时跳过 `NULL`。迁移时把历史 `wechat_api` 来源（备注以"微信 datacube 同步"开头）中的 0 改为 `NULL`。
3. **作品表现统一取"第 7 天"的值**（没有第 7 天时取离 7 最近且 ≤ 7 的节点，并标注"第 N 天数据"）。现在多处查询取"最新一条快照"（`daily_stats.go`、`insights.go`、`review.go` 等），老作品天然数字大，比较不公平。统一成一个 SQL 视图或函数 `work_metric_d7`，所有统计改用它。
4. 数据完整度：作品卡片显示"1 / 3 / 7 天"三个点，已录的点亮；账号健康度"近 30 天复盘数据"项改为按节点完整度计分。

### 4.2 A 公众号接口同步（EX-DR-02，仅认证账号）

1. **接口**：主用 `datacube/getarticletotal`（图文群发总数据），它按文章返回发布后最多 7 天的**累计**数据，并带 `msgid`；`getarticlesummary` 不再用于写快照。每次请求跨度 1 天，回看最近 7 天（每天一次请求，共 7 次）。具体字段、跨度和调用额度以 V-020、V-021 核验为准。
2. **匹配**：
   - 首选文章编号：回填发布链接时（H-07），解析长链接里的 `mid`、`idx` 参数，存为 `work.wechat_msgid`（`mid_idx`），与接口返回的 `msgid` 精确匹配；
   - 短链接（`mp.weixin.qq.com/s/xxxx`）没有这两个参数时，退回"标题规范化后完全相同 + 发布日期相差不超过 1 天"；
   - 仍匹配不上或匹配到多篇的，放进"待匹配"列表，由人逐条指定作品，**不自动猜**。
3. **能力检测**：保存凭证并测试时，额外试调一次数据接口，结果存到账号（`datacube_state`：`ok` / `no_permission` / `unknown`）。`no_permission` 时数据同步按钮隐藏，复盘页直接引导截图识别。
4. **后台同步**：`datacube_state=ok` 的账号每天 10:00 后（数据通常次日可用，时间以 V-021 为准）由 `jobs.go` 后台跑一次，`markOnce` 保证每账号每天一次。账号可在运营设置里关闭（设置键 `metrics.wechat_auto`，默认开）。连续 3 天失败或返回无权限时自动关闭，并发一条通知。路由和设置命名避开 `schedule`、`cron`、`timer`（HC-05）。
5. **账号级数据**（P2）：`datacube/getusersummary`、`getusercumulate` 提供每日新增和取消关注、累计粉丝，存入 `account_metric_daily`，用于账号层面的涨粉趋势；单篇作品的涨粉接口不提供，不硬算。

### 4.3 D 低摩擦录入（EX-DR-03）

1. 提醒通知直接带作品和节点（"《标题》发布满 3 天"），点开即是**快录抽屉**：只显示该平台的字段（小红书：浏览、点赞、收藏、评论、分享、涨粉；公众号：阅读、点赞、在看、分享、评论、涨粉），数字键盘，回车跳下一格。
2. 快录抽屉同时提供"上传截图识别"（第 4.4 节）。
3. 合理性提示：比上一个节点小（累计数不应变小）、点赞大于浏览等，显示黄色提示，不阻止保存。
4. 工作台"待录数据"列表按节点列出，可在列表内展开逐篇录入。录入是逐篇提交；多篇一起补用作品列表页截图识别（第 4.4 节）或已有的粘贴回填。
5. 已被接口同步覆盖的作品和节点不再提醒。

### 4.4 C 截图识别（EX-DR-04）

**为什么主推**：两个平台的 App 和后台都有单篇数据页，截图是用户最熟悉、成本最低的动作；数据由用户自己提供，不涉及任何平台接口或登录态。两个平台后台都没有导出功能（V-006、V-011），截图识别是未认证账号唯一能批量补数据的方式，因此在 P0 完成后第一个开发。

1. 入口：快录抽屉、复盘页"导入数据"。一次可传 1–9 张截图（单篇数据页、作品列表页、公众号"内容分析"页都可以）。
2. AI 任务 `metric_screenshot`（需要模型路由支持图片输入，经济档视觉模型即可）：
   - 输入：截图，以及该账号近 30 天已发布作品的标题和发布日期（帮助对应作品）；
   - 输出：`{"rows":[{"title":"","published_at":"","day_hint":"","metrics":{"reads":1200,"likes":30},"raw_text":"截图中的原始文字"}]}`；
   - 校验：每个数字必须能在 `raw_text` 中找到原样或"1.2万 / 1.2w / 1,200"形式；单位换算由程序做，不由模型做；不确定的字段留空。
3. 结果页：左边截图、右边识别出的行，每行显示匹配到的作品（可改）、各字段（可改）、置信提示；**逐行确认导入**，`source=screenshot`。
4. 截图只用于识别，7 天后删除，不进素材库、不进记忆、不用于其他 AI 任务。
5. 准确率目标：在 20 张真实截图上字段准确率 ≥ 95%（V-023）；达不到时只用于"预填"，提示用户逐格核对。

### 4.5 B 导出文件模板（EX-DR-05，已取消）

2026-10-11 用户登录小红书创作服务平台和公众号后台实地查看，都没有"导出数据"按钮（V-006、V-011 已核验）。本层取消，DEV-DR07 不开发。

- 现有 CSV 导入（DEV-409）保留，用于用户自己整理的表格，不再宣称支持"平台导出文件"；界面文案中的"导入平台导出文件"改为"导入表格（CSV）"，随 DEV-DR04 一起改。
- 以后平台若增加导出功能，重新核验后另开任务，不复用 DEV-DR07 编号。

### 4.6 F 分析闭环（EX-DR-06、EX-DR-07）

1. **规则统计自动跑**（不调用模型）：作品第 7 天数据到齐时，自动刷新归因分组（标题长度、数字、发布时段、正文长度、支柱）和数据偏好（13 文档 A102），全部改用第 7 天口径。
2. **每周复盘草稿**（参数 `review.weekly_draft`：`off` / `on`，默认 `off`）：每周一在后台用经济档模型生成上周复盘草稿，通知"上周复盘草稿已生成"。草稿里的建议仍逐条采纳（UX-03），不采纳不影响任何东西。
3. **回流推荐**：已采纳的复盘结论进入每日推荐的"复盘驱动"来源（11 文档第 6 节）；未采纳的规则统计只在推荐理由里作为参考数据显示，不改变生成规则。
4. 数据不足时（近 30 天第 7 天数据少于 3 篇）不生成复盘草稿、不下结论，只提示"先补数据"。

## 8. 风险

| 风险 | 对策 |
| --- | --- |
| 截图识别把数字读错 | 数字必须能在原始文字中找到；人逐行确认；准确率不达标时只预填 |
| 截图里有私信、收益等敏感信息 | 只识别数据字段；截图 7 天删除；不进其他 AI 任务；界面提示"可只截数据区域" |
| 平台改版导致截图版式变化 | 识别只依赖截图中的文字和数字，不依赖固定坐标；识别不出的字段留空由人补 |
| 接口同步与手动录入对同一节点给出不同数 | 不同来源分开保存；统计时优先级 `wechat_api` > `file` > `screenshot` > `paste` > `manual`，界面显示来源 |
| 后台同步被理解为"定时自动化" | 只读数据、不发布不推送；命名避开 HC-05 关键词；在决策里写明 |
