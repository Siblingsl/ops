## 方法与边界

1. **本表是开发侧结构化自评 + 规则核查，不是第三方人类主编盲签**。`≤20% 修改率` 为按归档记录与结构化缺口的预估，不代表外部评审已签字。
2. 本批 `wc-04`、`wc-05`、`xhs-05` 按任务书固定段数执行（公众号 4 段、小红书 3 段），生成器取模型大纲的前 N 项；`xhs-06` 走 `OPT-U02` 快写模式（`organize-notes` → `apply`）。段数上限与模型大纲共同决定覆盖度，本轮未放宽段数重跑。
3. 词表检查覆盖“在当今快节奏的时代、总而言之、综上所述、值得注意的是、不仅如此、赋能、闭环、抓手”等 21 个短语；10 篇均为 **0 命中**。但词表 0 命中不等于人工读感完全没有 AI 味，句式复读、空泛解释另计入扣分。
4. 占位符检查覆盖 `【待核实】` / `TODO` / `TBD`；仅 `wc-05` 命中 1 处。
5. 历史 3+3 批次没有逐项归档产品检查明细（当时只留 `works.json` 的清理说明），本表如实标“未归档”，不补造检查结果。

## 本批 4 篇逐项扣分记录

### `wc-04`（1849 字，4 段）

- **结构 2/5**：标题“我们删掉了哪四栏”要求四栏逐一交代；实际 4 段为“结论—问题—读者—栏目一”，只写完“本周完成”一栏，后三栏没有对应段落。第 4 段标题直接写“栏目一”，读者会期待“栏目二/三/四”，正文却结束。
- **去 AI 味 3/5**：词表 0 命中；但“模板/栏目/读者”三个词在各段反复解释，段落之间是同一判断换说法。
- **人设 4/5**：符合“务实、先给结论、少形容词”的账号定位。
- **事实 4/5**：无外部数字/机构编造；“三件事”“四个问题”是作者自设写法，不是事实断言。事实检查将其判为“需要核实的数据”属规则偏严。
- **修改率 1/5**：按标题兑现，需要新增栏目二/三/四约 900–1100 字，超过终稿 50%，且需重写第 4 段收束。
- **其他客观瑕疵**：“几固定提示”缺量词；第 1 段“模板如果只让人按‘本周完成 / 下周计划 / 个人心得’填充”与第 2 段重复。

### `wc-05`（1815 字，4 段）

- **结构 3/5**：开头结论、读者、过程埋重点、公众号版四段能推进；但标题含“公众号和小红书”两端，正文只详写公众号版，另一端仅用“另一种版本”一句带过，结构不对称。
- **去 AI 味 4/5**：词表 0 命中；口语化过渡自然，但“先确认读者要拿走什么”一段有清单式“第一/第二/第三”。
- **人设 4/5**：符合账号定位，举例仍围绕周报，跨平台主题没有跑偏。
- **事实 3/5**：`公众号靠逻辑推进留住人、小红书靠首屏结论留住人`、`小红书读者通常先看开头几行` 均无素材逐字出处，产品事实检查标为“需要核实的人物或机构”；作为经验判断可接受，但发布前应加限定或补来源。
- **修改率 3/5**：需替换 1 处【待核实：需要的时间】、给平台差异表述加限定，约 20–30%。
- **其他客观瑕疵**：末段“时间如果没有确认，写成【待核实：需要的时间】”把提示语写进正文，属流程泄漏。

### `xhs-05`（421 字，3 段）

- **结构 2/5**：标题承诺“300 块只花这三处”，正文 3 段分别是“结论—别买摆件—台灯”，理线与增高架只在首段被点名，没有独立动作和价格。读者无法据此完成另外两处改造。
- **去 AI 味 3/5**：词表 0 命中；句子短、口语感在，但“先看两件事/下单前我会看两件事”重复同一句式。
- **人设 4/5**：第一人称、价格导向、搬家可带走，符合账号定位与禁词要求。
- **事实 4/5**：价格区间来自登记素材且正文写明“以实际页面为准”；没有编造具体品牌或链接。未给三项合计，但 60–150 + 40–80 + ≤30 的区间上限 260 元，与 300 元预算不冲突。
- **修改率 2/5**：补理线、增高架两段（含价格与动作）约 150–200 字，占终稿 35–45%。
- **其他客观瑕疵**：标题“我只花了这三处”是消费记录口吻，正文没有逐项花费，语气与证据不匹配。

### `xhs-06`（292 字，5 段，`OPT-U02` 快写）

- **结构 2/5**：`organize-notes` 返回的 Markdown 以一级标题开头，`apply` 只按 `## ` 切段，导致“# 每天通勤 40 分钟，我怎么攒出 3 个选题库”被写进首段正文，与作品标题重复；5 段中 4 段是“一个动作一句话”，没有开头钩子与收束。
- **去 AI 味 2/5**：词表 0 命中，但“不展开。不补逻辑。不当场写成文章。”“只记卡在哪里。不急着想答案。不把地铁变成写作时间。”形成机械的三连否定；整体像提纲，不像笔记。
- **人设 3/5**：第一人称与通勤场景符合定位，但缺少真实细节（哪条线、听到什么原话、卡在哪），人设是空的。
- **事实 5/5**：只讲方法，没有数字、机构、引语，未编造事实。
- **修改率 1/5**：要把 292 字骨架扩写成可发布口语笔记（补场景、例子、过渡），预计改写 ≥60%，并删除正文重复标题。
- **产品层问题（非稿件内容）**：快写模式把 `#` 一级标题留在正文，属 `applyOrganizedNotes` 的解析边界；本轮只记录、不改代码。

## 产品检查的误报与噪音（不影响稿件评分，但影响可用性）

1. **广告法“最/第一”误报**：`最后一段` 中的“最”、“第一，写出读者”中的“第一”被当成极限词；`wc-04` 2 次、`wc-05` 1 次、`xhs-06` 2 次。属词典匹配缺少词边界。
2. **事实检查对自设序号过严**：`三件事`、`四个问题`、`两个问题`、`三个抽屉` 被标为“需要核实的数据”；这些是作者的写法安排，不是统计数字。
3. **意见性表述被标“需要核实的人物或机构”**：如“公众号靠逻辑推进留住人”，规则把平台经验判断当成人物/机构事实。
4. **“有素材支撑”仍不等于事实为真**：产品自己也在 detail 中声明“仍需逐条确认”，不能把该状态当作人工核验通过。
5. **格式阻断与内容无关**：本批未上传封面/配图，`封面与裁剪区域`、`图片 0 张` 必然阻断；`AI 声明` 未确认也属发布前人工动作，不是文本质量缺陷。

## 结论

- 真实模型在“观点—大纲—逐段起草”链路下能稳定产出通顺、无套话、无编造的长文与短笔记；历史 6 篇达到修改率 ≤20% 的可用水平。
- 本批 4 篇暴露出两类真实问题：**固定 4/3 段上限与“标题列举多项”的题材冲突**（`wc-04`、`wc-05`、`xhs-05` 覆盖不全），以及 **`OPT-U02` 快写把一级标题写进正文、产出偏提纲**（`xhs-06`）。两类问题均已保留原文，未做美化或人工补写。
- 5+5 质量集因此为 **6/10 达标、4/10 需返工**；不把 10/10 写成已完成，也不把开发侧自评冒充第三方盲签。
