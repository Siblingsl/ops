## 四、适配器版本级熔断（DEV-PS21，2026-10-21 完成）

**背景**：§12 要求 `platform_schema_changed` 对 `adapter_version + platform` **全局熔断**（不只停单连接），恢复必须发布新 `mapping_version` 并重新实测。原实现里该错误码落入 `default` 分支，**什么都不做**。

**实现**：
- 新增迁移 `00051_platform_adapter_breaker.sql`：`platform_adapter_breaker` 表，按 `(platform, adapter_version)` 记录 `state=open`，带 `error_code`/`mapping_version`/`affected_connections` 证据；`WHERE state='open'` 的部分唯一索引保证同版本只有一条有效熔断。
- `applyRunFailureAction` 增加 `platform_schema_changed` 分支：先停该连接（`auto_collect=false`、`availability=degraded`），再调 `openAdapterBreaker` 按版本全局熔断；重复触发只更新受影响连接数。
- `claimPlatformRun` 的选取 SQL 增加 `NOT EXISTS (... platform_adapter_breaker ...)`，**熔断期间不领取**该版本任务。
- 新增 `adapterBreakerOpen` 供其它路径复用。

**顺带修掉的真实缺陷（关键）**：调度与手动采集读取能力快照时用的是**下划线键名** `adapter_version`/`mapping_version`/`browser_version`，而客户端实际提交的是**驼峰** `adapterVersion`/`mappingVersion`。实测证据：`capabilities->>'adapterVersion'` 返回 `xhs-1`，`capabilities->>'adapter_version'` 返回 `NULL`。后果是 `platform_sync_run.adapter_version` **一直是空**，版本熔断根本无从判断。三处键名已改为驼峰，并加 `coalesce` 兜住缺键（旧数据无该键时原本会 `cannot scan NULL into *string` 直接崩调度）。

**测试**：新增 `server/internal/app/platform_breaker_test.go`（3 条）：
1. `platform_schema_changed` 触发版本级熔断，且记录保留错误码与受影响连接数、连接停掉自动采集；
2. 熔断按 `(平台, 版本)` 隔离——同平台其它版本、其它平台同名版本均不受影响；
3. 熔断期间 `claim` 拿不到任务。

**变异验证**：去掉 `platform_schema_changed` 分支 → 2 条测试失败；去掉 claim 的熔断拦截 → 1 条失败。

**实际命令与结果**：`go vet ./...` 通过；`go test ./internal/app -run 'TestHC|TestPlatform|TestMetric'` 通过（HC 35 未减少）；`go test ./internal/db` 通过（迁移版本断言由 50 更新为 51）；`desktop: pnpm typecheck`/`pnpm test` 通过/119 通过；`web: pnpm typecheck`/`test:unit` 通过/19 通过。

**未覆盖项**：熔断的**恢复**（发布新 `mapping_version` 后置 `state='resolved'`）尚无接口与界面，目前需人工改库；`browserVersion` 客户端从未提交，`run.browser_version` 仍为空。
